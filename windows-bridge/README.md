# پل سخت‌افزار ویندوز

برنامه‌ی دسکتاپ ویندوز برای اتصال چند پرینتر، ترازو و پیجر به صف دستگاه‌های منو. پردازش صف، ارتباط با شبکه/پورت سریال و چاپ رسید در Rust انجام می‌شود؛ رابط فارسی برنامه برای تنظیم و مشاهده‌ی وضعیت است.

## دریافت نصب‌گر

از لینک مستقیم [دانلود نصب‌گر Windows](https://github.com/asroDesign/menu_online/releases/download/windows-bridge-latest/MenuPeak-Bridge-Setup-x64.exe) فایل Setup را دریافت و اجرا کنید. این فایل پس از هر build موفق روی شاخهٔ `main` به‌روزرسانی می‌شود. اگر هنوز نخستین build موفق پس از فعال‌شدن انتشار مستقیم انجام نشده، آخرین اجرای موفق [GitHub Actions](https://github.com/asroDesign/menu_online/actions/workflows/windows-bridge.yml) را باز کنید و فایل artifact را موقتاً از بخش **Artifacts** دریافت کنید. هر تغییر در `windows-bridge/` یا workflow نیز build را اجرا می‌کند.

فایل artifact در Actions برای عیب‌یابی و نگهداری سی‌روزه باقی می‌ماند؛ job انتشار فایل Setup را حتی اگر داخل پوشه‌های تو در توی artifact باشد پیدا می‌کند و لینک مستقیم Release را به‌روز می‌سازد. Release پایدار منتشر شده و دکمهٔ پنل به همان فایل مستقیم متصل است؛ دانلود روزمره نیازی به بازکردن صفحهٔ GitHub Actions ندارد.

## راه‌اندازی

۱. در پنل رستوران، از بخش پرینتر/ترازو یا پیجر فایل ترکیبی `bridge.config.json` را دانلود کنید؛ این فایل همه‌ی دستگاه‌هایی را که پلن اجازه می‌دهد در همان عامل اجرا می‌کند. تنظیمات کارتخوان از پل قدیمی Node.js استفاده می‌کند و در این نسخه‌ی ویندوزی قابل اجرا نیست.
۲. برنامه را باز کنید و فایل JSON را انتخاب کنید یا متن آن را جای‌گذاری کنید؛ سپس «ذخیره‌ی تنظیمات» و «شروع اتصال» را بزنید.
۳. اگر می‌خواهید برنامه پس از ورود به Windows اجرا شود، گزینه‌ی «اجرای خودکار با Windows» را روشن کنید. برای شروع خودکار ارتباط، تنظیمات معتبر را یک بار ذخیره کرده باشید.

«شروع اتصال» فقط دریافت دوره‌ای jobهای سرور را فعال می‌کند و به‌تنهایی چیزی به پرینتر نمی‌فرستد. برای جداکردن عیب اتصال/درایور از مشکل صف ابری، روی کارت همان پرینتر «چاپ آزمایشی محلی» را بزنید؛ رسید کوتاهی مستقیماً با تنظیمات ذخیره‌شده‌ی همان کارت ارسال می‌شود و نیاز به اتصال سرور ندارد. اگر چاپ محلی موفق بود ولی سفارش چاپ نشد، گزارش باید بگوید صف سرور خالی است یا چند job دریافت شده؛ تنظیمات مسیردهی و صف `/dashboard/printers` را بررسی کنید. اگر چاپ محلی شکست خورد، متن خطا در toast و گزارش ارتباط مشخص می‌کند probe یا ارسال به درگاه Windows کجا ناموفق بوده است. موفقیت به معنی پذیرش داده توسط spooler/درگاه است؛ کاغذ را خودتان بررسی کنید.

تنظیمات در `%APPDATA%\DigitalMenuBridge\bridge.config.json` ذخیره می‌شوند. برنامه برای ارتباط خروجی HTTPS به سرور و اتصال TCP/Serial محلی نیاز دارد.

## دستگاه‌های پشتیبانی‌شده

- پرینتر شبکه‌ای ESC/POS با TCP (پورت رایج 9100)
- پرینتر Serial/USB-Serial با پورت COM
- پرینتر USB که در Windows نصب شده باشد؛ نام صف چاپگر را در تنظیمات پنل وارد کنید. صف چاپگر باید داده‌ی RAW/ESC-POS را عبور دهد.
- ترازوی شبکه یا Serial با درخواست، پایان پاسخ و Regex قابل تنظیم
- ترازوی USB HID با Vendor ID، Product ID، بایت درخواست و Regex متناسب با مدل دستگاه
- فرستنده‌ی پیجر شبکه یا Serial با قالب فرمان قابل تنظیم؛ وضعیت اتصال فقط پس از بررسی واقعی پورت/شبکه گزارش می‌شود. این بررسی دریافت فرمان توسط خود پیجر را ثابت نمی‌کند.

کارتخوان و تبلت از این برنامه پشتیبانی نمی‌شوند. برای کارتخوان از پل Node.js فعلی استفاده کنید؛ تبلت آشپزخانه همچنان از صفحه‌ی وب خودش استفاده می‌کند. پشتیبانی USB HID ترازو به مدل و دسترسی Windows به رابط HID آن بستگی دارد؛ اگر دستگاه به‌صورت HID قابل بازشدن نبود، از پورت COM یا مبدل USB-Serial آن استفاده کنید.

## ساخت محلی

برای ساخت نسخه‌ی ویندوزی به Rust، ابزارهای C++ ویندوز و WebView2 نیاز است. از مسیر `windows-bridge/src-tauri` اجرا کنید:

```powershell
cargo install tauri-cli --version "^2" --locked
cargo tauri build --bundles nsis
```

خروجی در `target/release/bundle/nsis/` قرار می‌گیرد. workflow بالا همین فرمان را روی Windows اجرا و فایل Setup را به‌صورت artifact نگه می‌دارد.

### کشف چاپگرهای نصب‌شده
پس از واردکردن تنظیمات و توقف اتصال، «کشف / بازخوانی چاپگرها» صف‌های USB و شبکه نصب‌شده در Windows را نشان می‌دهد. برای هر دستگاه پنل، صف موردنظر را انتخاب، تنظیمات را ذخیره و اتصال را شروع کنید. انتخاب چاپگر بدون ذخیره اعمال نمی‌شود. نقش و دسته‌بندی در پنل تعیین می‌شود. عامل محلی برای USB وجود صف و پرچم‌های خطای Windows را بررسی می‌کند؛ برای TCP/Serial بازشدن واقعی پورت را می‌سنجد. نتیجه‌ی موفق چاپ یعنی داده به صف Windows یا درگاه دستگاه تحویل شده است و به‌تنهایی خروج کاغذ را تضمین نمی‌کند. قابلیت فیزیکی در محیط توسعه‌ی macOS آزمون نشده است.

وضعیت آنلاین چاپگر/پیجر تنها با heartbeat عامل محلی پس از probe واقعی ثبت می‌شود و پس از ۱۵ ثانیه منقضی می‌شود. endpoint مرورگر `GET /api/device/:code/ping` وضعیت اخیر را فقط می‌خواند و نمی‌تواند دستگاه را آنلاین کند. `POST /api/device/:code/ping {connected}` وضعیت probe عامل را ثبت می‌کند. تست چاپ فقط به چاپگر دارای heartbeat تازه کار می‌فرستد و تا نتیجه‌ی عامل صبر می‌کند؛ در صورت timeout موفقیت نشان داده نمی‌شود. تست فرستنده‌ی پیجر وجود پورت/شبکه را می‌سنجد؛ برای بررسی زنگ واقعی، دکمه‌ی تست شماره‌ی ۱ در بخش پیجر را بزنید.
