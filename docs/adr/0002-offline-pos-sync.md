# ADR 0002: آفلاین POS و همگام‌سازی

وضعیت: پذیرفته‌شده برای برنامه‌ریزی؛ قابلیت اجرا نشده است.

## زمینه

ثبت سفارش، محاسبه قیمت، موجودی، تسویه و صف چاپ در سرویس فعلی به API و PostgreSQL وابسته‌اند. کلاینت‌های صندوق و کیوسک مرورگری هستند و قرارداد همگام‌سازی آفلاین یا ثبت محلی durable ندارند. عامل چاپ/ترازو به‌تنهایی حالت آفلاین صندوق ایجاد نمی‌کند.

## تصمیم معماری پیشنهادی

هر دستگاه باید شناسه و کلید چرخش‌پذیر ثبت‌شده داشته باشد. سفارش آفلاین در پایگاه محلی رمزگذاری‌شده با UUID idempotency ذخیره شود، snapshot قیمت/گزینه/مالیات را نگه دارد و وضعیت «در انتظار همگام‌سازی» را واضح نمایش دهد. هنگام اتصال، سرور با همان idempotency key سفارش را یک بار بپذیرد یا تعارض قابل حل برگرداند. سرور مرجع نهایی موجودی، شماره سفارش، پرداخت و حسابداری می‌ماند.

پیش از فعال‌سازی باید تعارض تغییر قیمت/منو، کمبود موجودی، سفارش تکراری، لغو و بازپرداخت، ساعت دستگاه، حذف برنامه و حفاظت داده روی دستگاه تعریف و آزموده شود. پرداخت برون‌خط یا تضمین تسویه آفلاین در این تصمیم پوشش ندارد و نباید ادعا شود. قابلیت rollout اولیه باید فقط سفارش cash-on-delivery با وضعیت pending-sync و اندازه محدود queue را بررسی کند.

## معیار ورود به پیاده‌سازی

- threat model برای دستگاه گم‌شده/مشترک و چرخش کلید.
- پروتکل idempotency و نسخه‌بندی payload.
- آزمون قطع اتصال، همگام‌سازی چندباره، تعارض و restart.
- تعیین رفتار چاپ تکراری و ارجاع رویداد به printer queues.
- اندازه‌گیری صف، retry/backoff، مانیتورینگ و بازیابی داده.
