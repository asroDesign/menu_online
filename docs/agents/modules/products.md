# محصولات منو

> راهنمای بازسازی عامل برای صفحه‌ی ثابت داشبورد.

- مسیر: `/dashboard/products`
- منبع: `src/app/dashboard/products/page.tsx`
- هدف: کاتالوگ کالا/غذا و منبع قیمت برای سفارش عمومی و صندوق.

## رابط و رفتار

جست‌وجو و فیلتر دسته/وضعیت، grid/list محصولات، افزودن/ویرایش modal شامل نام، توضیح، قیمت جاری/قبلی، دسته، emoji/icon، تصویر، زمان آماده‌سازی، موجودی/فعال و featured؛ آپلود تصویر با ImageUpload؛ حذف با تأیید.

## API و داده

GET/CRUD /api/products؛ GET /api/categories؛ upload از API upload.

## الزامات بازنویسی

قیمت سمت سرور سفارش بازاعتبارسنجی شود؛ محصول ناموجود/غیرفعال در منوی عمومی سفارش‌پذیر نیست؛ حذف محصول و recipes/orders باید ایمن باشد.

این صفحه باید با shell مشترک داشبورد و اصول UI/RTL در `README.md` این پوشه هماهنگ باشد. برای schema کامل، منبع و routeهای API ذکرشده را بخوان.

## مشخصات سطح پیاده‌سازی

### فرم و کاتالوگ

فرم ویرایش شامل `name` (اجباری)، `description`، `price`، `oldPrice`، `categoryId` (اختیاری)، نماد تصویری فعلی، `imageUrl`، `prepMinutes`، `isAvailable`، `isFeatured` و `arModelUrl` است. قیمت با ارقام فارسی/انگلیسی پذیرفته می‌شود، باید عدد متناهی و نامنفی باشد؛ نام trim شود. قیمت قبلی اختیاری است و درصد تخفیف فقط وقتی `oldPrice > price` محاسبه شود. زمان آماده‌سازی پیش‌فرض ۱۰ دقیقه است.

صفحه دو collection مستقل `/api/products` و `/api/categories` می‌خواند. جستجو در نام و توضیح و فیلتر دسته‌ها شامل «همه» و «بدون دسته» است. کارت هر محصول تصویر/نماد، دسته، زمان آماده‌سازی، توضیح کوتاه، قیمت فعلی/قدیم، وضعیت موجودی و ویژه بودن را نشان می‌دهد. کنترل موجود/ناموجود و ویژه‌بودن روی همان ردیف patch می‌شوند. آپلود تصویر از `ImageUpload` انجام می‌شود؛ URL مدل سه‌بعدی ورودی جداگانه دارد و نباید با تصویر محصول یکی گرفته شود.

### ذخیره، حذف و اتصال

ایجاد از `products.create` و ویرایش از `products.update` استفاده می‌کند؛ در نمایش خوش‌بینانه، رکورد موقت شناسه منفی دارد و خطای API باید rollback شود. قبل از حذف `ConfirmDialog` لازم است. گروه خالی/خطای بارگیری/شکست دسته‌ها و محصولات به‌درستی نمایش داده شوند. API واقعی و محدودیت اندازه فایل را از `src/app/api/products`, `src/app/api/upload` و `src/components/image-upload.tsx` بخوان؛ client validation جای بررسی مالکیت tenant، شکل URL یا مقدار عددی در سرور نیست.

### معیار پذیرش

بعد از تغییر موجودی، منوی عمومی همان محصول را سفارش‌پذیر/غیرقابل‌سفارش کند؛ کالا و قیمت نهایی سفارش در backend از کاتالوگ tenant استخراج شود، نه از مبلغ ارسالی مشتری. حذف کالای دارای ارجاع باید مطابق محدودیت دیتابیس/API مدیریت شود و نباید recipe یا سفارش تاریخی را بی‌صدا خراب کند. Modal در موبایل قابل پیمایش و فیلدهای قیمت/شناسه در جهت LTR و قابل ورود با صفحه‌کلید عددی باشند.
