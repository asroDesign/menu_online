# درآمد و هزینه

> مشخصات بازسازی ماژول `income-expense` برای عامل پیاده‌سازی. این سند رفتار و قرارداد ماژول فعلی را خلاصه می‌کند؛ اگر اختلافی با کد زنده وجود داشت، کد و API فعلی منبع حقیقت هستند.

## جایگاه و دسترسی

- مسیر پنل: `/dashboard/income-expense`
- کامپوننت/منبع فعلی: `src/modules/finance.tsx — IncomeExpense / LedgerPage`
- entitlement تعرفه: `income_expense`
- هدف: دفتر روزنامه ساده برای درآمدهای متفرقه و هزینه‌های جاری.

## رابط و جریان کار

لیست ثبت‌ها با بازه تاریخ و جمع درآمد/هزینه/خالص؛ فرم ثبت نوع، دسته (انتخاب حساب معین)، حساب تفصیلی (در صورت وجود)، مبلغ، حساب بانکی/صندوق، تاریخ شمسی و شرح؛ حذف/ویرایش مجاز طبق API. دستهٔ فرم همان انتخاب حساب معین است و فیلد متنی دسته‌بندی جداگانه ندارد. با تغییر نوع درآمد/هزینه، انتخاب دسته و تفصیلی قبلی پاک می‌شوند تا سرفصل اشتباه باقی نماند.

## داده و API

Resource-style LedgerPage روی `/api/r/incomeexpense`؛ حساب بانکی از `/api/r/bank` و سرفصل‌های مجاز از `GET /api/income-expense/accounts`.

## قواعدی که بازنویسی باید حفظ کند

ورودی amount مثبت و kind معتبر؛ دسته باید یک حساب معین سازگار با نوع و ماهیت ردیف باشد؛ حساب بانکی optional و صندوق نقدی پیش‌فرض؛ فروش سفارش با این فرم دوباره ثبت نشود.

- وضعیت‌های loading، خطا، داده خالی و موفقیت را جدا و قابل فهم نشان بده؛ خطا را با امکان تلاش مجدد مدیریت کن.
- رابط فارسی و RTL، ارقام فارسی، پول تومان، و تاریخ‌های شمسی را مطابق ابزارهای مشترک پروژه نمایش بده.
- layout را برای موبایل/تبلت/دسکتاپ بازسازی کن؛ فرم‌ها و جدول‌ها در عرض کم قابل استفاده بمانند و اکشن اصلی از دسترس خارج نشود.
- عملیات را با componentهای مشترک `src/components/ui.tsx`, `src/components/resource-page.tsx` و `src/lib/api.ts` هم‌راستا کن؛ بعد از mutation فهرست/cache را تازه کن.
- tenant isolation، احراز هویت، entitlement و نقش باید سمت API نیز enforce شود؛ مخفی کردن دکمه به‌تنهایی مجوز نیست.

## مشخصات سطح پیاده‌سازی

این page از shared `LedgerPage` با endpoint `/api/r/incomeexpense` است. رکورد `kind=income|expense`, `amount` تومان مثبت، `category`, nullable `bankAccountId`, `accountMoeinId`, nullable `accountTafsiliId`, `date`, `description` را نگه می‌دارد. در فرم، کنترل با برچسب «دسته» همان انتخاب `accountMoeinId` است؛ فیلد متنی جداگانهٔ `category` نمایش داده نمی‌شود. `category` در مدل و API برای سازگاری رکوردهای قبلی حفظ شده و برای ردیف‌های جدیدِ ثبت‌شده با حساب، مقدار پیش‌فرض خالی می‌ماند؛ جدول نام حساب معین منتخب را به‌عنوان دسته نمایش می‌دهد و برای رکوردهای قدیمی بدون حساب از `category` ذخیره‌شده استفاده می‌کند. حساب‌های دسته از `GET /api/income-expense/accounts` می‌آیند که با entitlement `income_expense` و tenant نشست احراز‌شده محدود است؛ فقط معین فعال درآمد با ماهیت بستانکار برای درآمد و معین فعال هزینه با ماهیت بدهکار برای هزینه برمی‌گردد. تفصیلی فعال باید فرزند معین انتخاب‌شده و دارای همان نوع/ماهیت باشد. اگر معین تفصیلی سازگار داشته باشد انتخاب آن لازم است؛ در غیر این صورت posting روی خود معین انجام می‌شود. انتخاب حساب‌ها سمت API نیز از نظر کسب‌وکار، سطح، رابطه پدر/فرزند، فعال‌بودن، نوع و ماهیت بررسی می‌شود.

معین/تفصیلی در `transactions.account_moein_id` و `transactions.account_tafsili_id` ذخیره و با migration `0025_income_expense_accounts.sql` به حساب‌ها ارجاع داده می‌شوند. `postManualTx` برای درآمد، صندوق/بانک را بدهکار و حساب معین/تفصیلی منتخب را بستانکار می‌کند؛ برای هزینه حساب منتخب بدهکار و صندوق/بانک بستانکار می‌شود. ردیف‌های قدیمی که شناسه حساب ندارند با نگاشت دسته‌بندی قبلی قابل posting باقی می‌مانند. انتخاب خالی حساب بانکی یعنی صندوق نقدی. تاریخ input جلالی با default امروز است. جمع KPI بر اساس ردیف‌های بارگیری‌شده: درآمد، هزینه و خالص. جدول تاریخ، نوع با رنگ، دسته/source sale badge، شرح، حساب معین/تفصیلی، صندوق/بانک و مبلغ علامت‌دار را نشان می‌دهد.

API scope `source <> 'sale'` دارد، پس sale-generated rows در ثبت دستی income/expense تکراری نمی‌شوند. writer role در registry accountant است (علاوه بر owner/manager)؛ فیلد amount باید حداقل ۱ باشد و post/unpost ledger دوطرفه در `withPosting` به‌صورت hook انجام می‌شود. تاریخ UI date-only را به ISO تبدیل می‌کند.

**پذیرش:** income/expense، انتخاب «دسته» (حساب معین) و تفصیلی سازگار با ماهیت، cash و bank، روز شمسی، ثبت در حسابداری با حساب انتخاب‌شده و حذف/ویرایش که posting قبلی را reverse/repost کند؛ فرم نباید یک ورودی متنی دستهٔ تکراری نشان دهد و ثبت source=sale را به UI دستی اجازه ندهد. پیش از اجرای نسخه‌ای که پیوند حساب‌ها را اضافه می‌کند، migration `0025_income_expense_accounts.sql` روی دیتابیس اعمال شود؛ rollback آن ستون‌های انتخاب حساب را حذف و انتخاب‌های ذخیره‌شده را از بین می‌برد.

## مرجع بازسازی

برای جزئیات دقیق فیلدها، ترتیب کنترل‌ها، پیام‌های فارسی و قرارداد typeها، فایل منبع بالا را همراه API route متناظر در `src/app/api` بخوان. این راهنما رفتار را مشخص می‌کند و جایگزین بررسی source-of-truth نیست.
