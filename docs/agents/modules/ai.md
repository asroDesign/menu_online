# دستیار هوشمند

> مشخصات بازسازی ماژول `ai` برای عامل پیاده‌سازی. این سند رفتار و قرارداد ماژول فعلی را خلاصه می‌کند؛ اگر اختلافی با کد زنده وجود داشت، کد و API فعلی منبع حقیقت هستند.

## جایگاه و دسترسی

- مسیر پنل: `/dashboard/ai`
- کامپوننت/منبع فعلی: `src/modules/growth-b.tsx — AiPage`
- entitlement تعرفه: `ai`
- هدف: پیشنهاد متن بازاریابی/توضیح محصول با انتخاب محصول و لحن.

## رابط و جریان کار

نمایش آمار/سهمیه یا قابلیت، انتخاب محصول، tone، دکمه تولید و پنل خروجی قابل کپی؛ loading/error/empty.

## داده و API

GET/POST /api/r/ai؛ POST body شامل productId و tone.

## قواعدی که بازنویسی باید حفظ کند

متن تولیدی draft است و خودکار روی منو ذخیره/منتشر نشود؛ داده و سهمیه از سرور؛ خطای provider به UI قابل فهم تبدیل شود.

- وضعیت‌های loading، خطا، داده خالی و موفقیت را جدا و قابل فهم نشان بده؛ خطا را با امکان تلاش مجدد مدیریت کن.
- رابط فارسی و RTL، ارقام فارسی، پول تومان، و تاریخ‌های شمسی را مطابق ابزارهای مشترک پروژه نمایش بده.
- layout را برای موبایل/تبلت/دسکتاپ بازسازی کن؛ فرم‌ها و جدول‌ها در عرض کم قابل استفاده بمانند و اکشن اصلی از دسترس خارج نشود.
- عملیات را با componentهای مشترک `src/components/ui.tsx`, `src/components/resource-page.tsx` و `src/lib/api.ts` هم‌راستا کن؛ بعد از mutation فهرست/cache را تازه کن.
- tenant isolation، احراز هویت، entitlement و نقش باید سمت API نیز enforce شود؛ مخفی کردن دکمه به‌تنهایی مجوز نیست.

## مشخصات سطح پیاده‌سازی

صفحه دو کارت مستقل دارد. کارت اول GET `/api/r/ai` برای insightهای ۱۴ روزه: engine، tips، top products/qty، slow products، lowStock، avgTicket و hasOrders/peakHour. engine badge تفاوت OpenAI با تحلیل داخلی را نشان می‌دهد. اگر `err` وجود داشت ErrorState، در غیر این صورت loading skeleton تا داده برسد. hint زیر صفحه می‌گوید OPENAI_API_KEY فقط روی server تنظیم شود.

کارت دوم محصول انتخابی (اولین محصول پیش‌فرض) و tone `friendly|luxury|short` دارد. POST `{productId,tone}` متن تولیدی و engine را برمی‌گرداند؛ خروجی فقط draft در حافظه است. «اعمال روی محصول» با PATCH محصول description را تغییر می‌دهد؛ تولید به خودی خود save یا publish نیست. دکمه generate loading دارد و در نبود محصول disabled.

**پذیرش:** no product، no orders insight، low stock، API fail، generation busy و متن خروجی بدون اعمال/پس از apply را بررسی کن؛ در هر حالت engine را واضح نشان بده.

## مرجع بازسازی

برای جزئیات دقیق فیلدها، ترتیب کنترل‌ها، پیام‌های فارسی و قرارداد typeها، فایل منبع بالا را همراه API route متناظر در `src/app/api` بخوان. این راهنما رفتار را مشخص می‌کند و جایگزین بررسی source-of-truth نیست.
