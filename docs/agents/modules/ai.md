# دستیار هوشمند و ساخت منو

> راهنمای بازسازی ماژول داشبورد `/dashboard/ai`. این ماژول دو بخش دارد: ساخت/آماده‌سازی منو و تحلیل فروش. کد جاری مرجع نهایی است.

## نقش و دسترسی

- صفحه: `src/modules/growth-b.tsx — AiPage`
- entitlement: `ai`; دسترسی mutationهای منو علاوه بر آن به مدیر کسب‌وکار محدود است.
- UI ساخت منو: `src/components/ai-menu-builder.tsx`؛ پیش‌نمایش بازاریابی: `src/components/marketing/ai-page-interactions.tsx`.
- APIهای تازه: `POST/PUT /api/ai/menu/parse` و `POST /api/ai/menu/image`.
- APIهای قبلی: `GET/POST /api/r/ai` برای تحلیل ۱۴روزه و تولید متن توضیح یک محصول.

## ساخت پیش‌نویس منو

چهار مسیر در تب‌ها وجود دارد:

1. **از فهرست غذاها:** مدیر نام هر قلم را وارد می‌کند؛ در صورت امکان دسته/قیمت/شرح را هم وارد می‌کند. با وجود `OPENAI_API_KEY`، فهرست تا ۲۰هزار نویسه به OpenAI Chat Completions (`gpt-4o-mini`) فرستاده می‌شود تا JSON حداکثر ۵۰ قلم استخراج شود. بدون کلید، parser قاعده‌محور خطوط و جداکننده‌های ویرگول/تب/pipe را می‌خواند؛ این fallback، مدل زبانی نیست.
2. **از عکس منوی فعلی:** PNG/JPEG/WebP حداکثر ۲٫۵ مگابایت انتخاب می‌شود. signature واقعی فایل با MIME بررسی می‌شود. استخراج OCR/نام/دسته/قیمت از vision API انجام می‌شود و به کلید سرور نیاز دارد؛ حدس قیمت باید `null` بماند.
3. **نوشتن توضیحات محصول:** محصول و لحن انتخاب می‌شود؛ `POST /api/r/ai` draft می‌سازد. مدیر متن را بازبینی می‌کند و با اقدام جداگانه به محصول ذخیره می‌کند.
4. **ساخت/بهبود عکس:** نام و شرح اختیاری وارد می‌شود؛ انتخاب عکس ورودی حالت edit را فعال می‌کند. `POST /api/ai/menu/image` به GPT Image 2.5 Sunburst درخواست می‌فرستد و WebP را در `uploads` همان tenant ذخیره می‌کند. تصویر draft منو تا زمان ثبت preview است؛ انتخاب اختیاری محصول موجود به‌معنی درخواست صریح مدیر برای ذخیرهٔ تصویر روی همان محصول است.

پس از استخراج، مدیر نام، دسته، توضیح، قیمت و تصویر هر قلم را ویرایش می‌کند. تکرار نام در یک دسته هنگام ارسال رد می‌شود؛ اگر محصولی با همان دسته/نام از قبل باشد سرور آن را skip می‌کند. ساخت دسته‌ها و محصولات در transaction انجام می‌شود. قیمت خالی در draft به صفر تبدیل می‌شود، اما هر محصول تازه با `isAvailable:false` می‌سازد تا منتشر یا قابل سفارش نشود؛ مدیر باید قیمت و اطلاعات را کامل کند و بعد از صفحه محصول آن را فعال کند. هیچ مرحلهٔ ساخت منو خودکار محصول را منتشر نمی‌کند.

## تحلیل و قابلیت‌های متصل

- `GET /api/r/ai` تحلیل سفارش‌های پرداخت‌شدهٔ ۱۴ روز اخیر، پرفروش‌ها، اقلام بدون فروش، زمان اوج، میانگین فاکتور و موجودی کم را می‌دهد. تحلیل فعلی عمدتاً قواعد و دادهٔ همان کسب‌وکار است؛ وجود API key به‌تنهایی به معنای تولید insights با LLM نیست.
- پیشنهاد مکمل از `/dashboard/cross-sell` و دادهٔ ترکیب خرید/دسته‌بندی می‌آید و به‌تنهایی AI مولد نیست.
- سفارش QR و منوی دیجیتال در مسیر public-menu موجود است؛ موجودی/وضعیت آیتم باید مدیرانه کنترل شود. این ماژول زمان‌بندی یا پنهان‌سازی خودکار محصول بر اساس ساعت ندارد.
- برآورد صفحهٔ بازاریابی یک حسابگر آموزشی فروش ناخالص است: تعداد سفارش روزانه × ۳۰ × درصد پذیرش × قیمت مکمل. آن را درآمد تضمینی یا سود خالص معرفی نکن.

## معرفی عمومی قابلیت‌ها در `/ai`

- صفحهٔ عمومی چهار مسیر محتوایی را نشان می‌دهد: ساخت پیش‌نویس از فهرست، استخراج از عکس منو، نوشتن توضیح محصول و ساخت/بهبود تصویر. پنل‌های تعاملی نمونهٔ نمایشی‌اند؛ آن‌ها API provider یا workflow داخلی را افشا نمی‌کنند.
- دو ابزار متصل نیز جداگانه برچسب می‌خورند: تحلیل فروش ۱۴روزه مبتنی بر داده/قواعد و پیشنهاد مکمل بر پایهٔ ترکیب خرید/قواعد. آن‌ها نباید به‌عنوان خروجی مولد مدل یا «مدیریت خودکار» تبلیغ شوند.
- خروجی ساخت محتوا پیش‌نویس است و انتشار/فعال‌سازی با مدیر می‌ماند. صفحهٔ بازاریابی روشن و ریسپانسیو است، انیمیشن CSS دارد و `prefers-reduced-motion` را رعایت می‌کند.
- برای copywriting عمومی از نام مدل، prompt، provider، جزئیات rate limit یا دستورالعمل داخلی استفاده نکن؛ مزیت قابل مشاهده و کنترل کاربر را شرح بده، بدون ادعای جلوگیری قطعی از کپی‌برداری از UI عمومی.

## امنیت، محدودیت، و وابستگی

- تمام APIها tenant را از `withAuth` می‌گیرند؛ endpointهای parse/image شرط manager و entitlement `ai` دارند، ورودی محدود است و به تفکیک کسب‌وکار/کاربر rate limit دارند.
- تصویر و دادهٔ menu به tenant دیگری متصل نمی‌شود؛ URL فایل هنگام save بررسی مالکیت دارد.
- `OPENAI_API_KEY` فقط روی سرور خوانده می‌شود؛ هرگز آن را در client یا log ثبت نکن. OCR تصویر، تولید متن مدل‌محور و تولید/ویرایش تصویر به کلید، دسترسی شبکهٔ سرور و هزینهٔ provider نیاز دارند. fallback متن فقط استخراج ساده است.
- تحلیل و قواعدی که از قبل وجود داشتند در صورت نبود کلید همچنان کار می‌کنند؛ پیام provider به‌صورت خطای روشن به کاربر می‌رسد.
- مدل تصویر را فقط از مستندات رسمی به‌روز انتخاب کن؛ `gpt-image-1` از ۲۰۲۶-۱۰-۲۳ بازنشسته شده و کد فعلی از `gpt-image-2.5-sunburst` استفاده می‌کند. [راهنمای رسمی تولید تصویر](https://developers.openai.com/api/docs/guides/image-generation) و [مرجع edit](https://developers.openai.com/api/reference/resources/images/methods/edit) را هنگام تغییر قرارداد بررسی کن.

## فایل‌ها و نگهداری

- `src/modules/growth-b.tsx`: داشبورد insights و اتصال builder.
- `src/components/ai-menu-builder.tsx`: تب‌ها، ورودی، draft editor، apply و save.
- `src/app/api/ai/menu/parse/route.ts`: parse و ثبت tenant-scoped دسته/محصول.
- `src/app/api/ai/menu/image/route.ts`: generation/edit و ذخیرهٔ فایل.
- `src/lib/registry-b.ts`: رفتار موجود GET/POST `/api/r/ai`.
- `src/db/schema.ts`: جدول‌های فعلی `categories`, `products`, `uploads`; تغییر schema/migration لازم نیست.

## آزمون پذیرش

- manager دارای entitlement می‌تواند هر مسیر را باز کند؛ نقش/پلن نامجاز API را رد می‌کند.
- فهرست متنی با و بدون key، OCR با عکس معتبر، عکس/داده خراب، عکس بزرگ، و provider timeout/error.
- editor پیش از تأیید: قیمت/دسته/شرح قابل اصلاح؛ duplicate name رد شود؛ duplicate DB skip شود؛ دسته/محصول transaction شود و همه محصولات تازه غیرفعال بمانند.
- تصویر generated/edit در preview نمایش داده شود؛ tenant دیگر نتواند فایل را پیوند دهد؛ ذخیرهٔ روی محصول فقط با انتخاب همان محصول.
- mobile: چهار tab در دو ستون، پنل عمودی و editor اسکرول‌پذیر؛ prefers-reduced-motion رعایت شود.
- API واقعی provider در آزمون local/CI mock شود؛ برای فعال‌سازی تولید، کلید server و بودجه/سقف مصرف باید مدیریت شوند.
