# کارکنان

> مشخصات بازسازی ماژول `staff` برای عامل پیاده‌سازی. این سند رفتار و قرارداد ماژول فعلی را خلاصه می‌کند؛ اگر اختلافی با کد زنده وجود داشت، کد و API فعلی منبع حقیقت هستند.

## جایگاه و دسترسی

- مسیر پنل: `/dashboard/staff`
- کامپوننت/منبع فعلی: `src/modules/staff.tsx — Staff`
- entitlement تعرفه: `cashier_pos`
- هدف: مدیریت کاربران عملیاتی رستوران و نقش/وضعیت دسترسی آنان.

## رابط و جریان کار

ResourcePage جدولی/کارتی با افزودن و ویرایش نام، شماره تماس، نقش و وضعیت فعال؛ جست‌وجو و حذف/غیرفعال‌سازی. نقش‌ها با برچسب فارسی و وضعیت واضح.

## داده و API

ResourcePage endpoint /api/staff؛ APIهای GET/POST/PATCH/DELETE آن.

## قواعدی که بازنویسی باید حفظ کند

محدودیت نقش‌ها و دسترسی واقعی در سرور اعمال شود؛ رمز/اطلاعات محرمانه دوباره نمایش داده نشود؛ کارکنان غیرفعال در انتساب سفارش انتخاب نشوند.

- وضعیت‌های loading، خطا، داده خالی و موفقیت را جدا و قابل فهم نشان بده؛ خطا را با امکان تلاش مجدد مدیریت کن.
- رابط فارسی و RTL، ارقام فارسی، پول تومان، و تاریخ‌های شمسی را مطابق ابزارهای مشترک پروژه نمایش بده.
- layout را برای موبایل/تبلت/دسکتاپ بازسازی کن؛ فرم‌ها و جدول‌ها در عرض کم قابل استفاده بمانند و اکشن اصلی از دسترس خارج نشود.
- عملیات را با componentهای مشترک `src/components/ui.tsx`, `src/components/resource-page.tsx` و `src/lib/api.ts` هم‌راستا کن؛ بعد از mutation فهرست/cache را تازه کن.
- tenant isolation، احراز هویت، entitlement و نقش باید سمت API نیز enforce شود؛ مخفی کردن دکمه به‌تنهایی مجوز نیست.

## مشخصات سطح پیاده‌سازی

Member fields: `name`, `role`, `phone`, `email`, `password`, `hasLogin`, `isActive`. فرم role از `STAFF_ROLE_LABELS` شامل مدیر شیفت، گارسون، صندوقدار، آشپزخانه، انباردار، حسابدار می‌سازد. Email برای ایجاد login است؛ password secret field و در edit خالی یعنی رمز فعلی تغییر نکند. UI بالای جدول توضیح می‌دهد دسترسی role با entitlement پلن اشتراک محدود است. جدول نشان نام/initial، تلفن، role badge، login وجود دارد/ندارد و active state؛ Switch فعال/غیرفعال با PATCH ردیف اجرا می‌شود.

API `/api/staff` اختصاصی است، نه resource generic؛ برای فیلد password و اینکه backend چه زمانی user می‌سازد/به‌روزرسانی می‌کند، `src/app/api/staff/route.ts` و `[id]/route.ts` را بخوان. هرگز hash/رمز فعلی را به کلاینت برنگردان؛ کارمند inactive باید از pickerهای waiter و auth خارج شود.

**پذیرش:** create بدون ایمیل به‌عنوان member و create با حساب login، role assignment، toggle active، خطای ایمیل تکراری، edit بدون تغییر password و role-restricted API را بررسی کن.

## مرجع بازسازی

برای جزئیات دقیق فیلدها، ترتیب کنترل‌ها، پیام‌های فارسی و قرارداد typeها، فایل منبع بالا را همراه API route متناظر در `src/app/api` بخوان. این راهنما رفتار را مشخص می‌کند و جایگزین بررسی source-of-truth نیست.
