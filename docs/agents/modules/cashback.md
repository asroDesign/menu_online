# اعتبار وفاداری

> مشخصات بازسازی ماژول `cashback` برای عامل پیاده‌سازی. این سند رفتار و قرارداد ماژول فعلی را خلاصه می‌کند؛ اگر اختلافی با کد زنده وجود داشت، کد و API فعلی منبع حقیقت هستند.

## جایگاه و دسترسی

- مسیر پنل: `/dashboard/cashback`
- کامپوننت/منبع فعلی: `src/modules/growth-a.tsx — Cashback`
- entitlement تعرفه: `cashback`
- هدف: مشاهده و تعدیل اعتبار نقدی/امتیاز کیف پول مشتریان.

## رابط و جریان کار

نمایش ledger رویدادهای کیف پول و فهرست مشتری؛ فرم تعدیل دستی مبلغ مثبت/منفی با یادداشت؛ جمع اعتبار و تازه‌سازی بعد از ثبت.

## داده و API

GET /api/r/walletlog؛ POST /api/r/walletlog؛ مشتری‌ها از /api/r/customers.

## قواعدی که بازنویسی باید حفظ کند

هر تغییر باید ledger entry داشته باشد؛ اعتبار منفی/مبلغ نامعتبر را UI و سرور رد کنند؛ لاگ باید actor و علت عملیات را نگه دارد.

- وضعیت‌های loading، خطا، داده خالی و موفقیت را جدا و قابل فهم نشان بده؛ خطا را با امکان تلاش مجدد مدیریت کن.
- رابط فارسی و RTL، ارقام فارسی، پول تومان، و تاریخ‌های شمسی را مطابق ابزارهای مشترک پروژه نمایش بده.
- layout را برای موبایل/تبلت/دسکتاپ بازسازی کن؛ فرم‌ها و جدول‌ها در عرض کم قابل استفاده بمانند و اکشن اصلی از دسترس خارج نشود.
- عملیات را با componentهای مشترک `src/components/ui.tsx`, `src/components/resource-page.tsx` و `src/lib/api.ts` هم‌راستا کن؛ بعد از mutation فهرست/cache را تازه کن.
- tenant isolation، احراز هویت، entitlement و نقش باید سمت API نیز enforce شود؛ مخفی کردن دکمه به‌تنهایی مجوز نیست.

## مشخصات سطح پیاده‌سازی

صفحه از دو مجموعه استفاده می‌کند: customers برای مانده و مشخصات، walletlog برای ledger. بالای ResourcePage، `CashbackSettingsCard` قوانین نرخ/حدود cashback را از business settings تنظیم می‌کند. جدول مشتری ستون نام/تلفن، اعتبار فعلی و مجموع خرید دارد؛ حذف customer در این صفحه disabled است. action تعدیل دستی prompt مبلغ می‌گیرد و مبلغ منفی برای کسر اعتبار مجاز است؛ note ثابت «تعدیل دستی توسط مدیر» و POST `/api/r/walletlog {customerId,amount,note}`.

پایین صفحه ۳۰ رخداد اخیر: `earn`, `spend`, `refund`, `adjust`, customerName, note, amount و زمان نسبی. مبلغ مثبت سبز و منفی قرمز با علامت، نوع رخداد badge رنگی. هر posting order/refund باید از سرویس‌های order/wallet باشد؛ دستی را با overwrite `walletBalance` جایگزین نکن.

**پذیرش:** ledger خالی، loading، مانده صفر، adjust با ارقام فارسی، error و reload هر دو customers/log؛ مبلغ ورودی خالی یا صفر نباید به تغییر ناخواسته تبدیل شود. چون `window.prompt` در UI فعلی است، اگر modal جدید پیاده می‌کنی همین رفتار منفی/توضیح را حفظ کن.

## مرجع بازسازی

برای جزئیات دقیق فیلدها، ترتیب کنترل‌ها، پیام‌های فارسی و قرارداد typeها، فایل منبع بالا را همراه API route متناظر در `src/app/api` بخوان. این راهنما رفتار را مشخص می‌کند و جایگزین بررسی source-of-truth نیست.
