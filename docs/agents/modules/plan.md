# تعرفه و اشتراک

> مشخصات بازسازی ماژول `plan` برای عامل پیاده‌سازی. این سند رفتار و قرارداد ماژول فعلی را خلاصه می‌کند؛ اگر اختلافی با کد زنده وجود داشت، کد و API فعلی منبع حقیقت هستند.

## جایگاه و دسترسی

- مسیر پنل: `/dashboard/plan`
- کامپوننت/منبع فعلی: `src/modules/growth-b.tsx — PlanPage`
- entitlement تعرفه: `بدون entitlement خاص`
- هدف: نمایش پلن فعلی، قابلیت‌ها، قفل‌های ماژول و درخواست ارتقا.

## رابط و جریان کار

GET وضعیت پلن و قابلیت‌ها؛ کارت‌های قابل مقایسه؛ locked query از لینک ماژول؛ درخواست انتخاب پلن و state انتظار تأیید مدیر.

## داده و API

GET/POST /api/plan با body {plan}; entitlementها از server-side auth/features.

## قواعدی که بازنویسی باید حفظ کند

نمایش پلن، قیمت و قابلیت باید از داده معتبر backend باشد؛ انتخاب پلن در UI به تنهایی فعال‌سازی دسترسی نیست.

- وضعیت‌های loading، خطا، داده خالی و موفقیت را جدا و قابل فهم نشان بده؛ خطا را با امکان تلاش مجدد مدیریت کن.
- رابط فارسی و RTL، ارقام فارسی، پول تومان، و تاریخ‌های شمسی را مطابق ابزارهای مشترک پروژه نمایش بده.
- layout را برای موبایل/تبلت/دسکتاپ بازسازی کن؛ فرم‌ها و جدول‌ها در عرض کم قابل استفاده بمانند و اکشن اصلی از دسترس خارج نشود.
- عملیات را با componentهای مشترک `src/components/ui.tsx`, `src/components/resource-page.tsx` و `src/lib/api.ts` هم‌راستا کن؛ بعد از mutation فهرست/cache را تازه کن.
- tenant isolation، احراز هویت، entitlement و نقش باید سمت API نیز enforce شود؛ مخفی کردن دکمه به‌تنهایی مجوز نیست.

## مشخصات سطح پیاده‌سازی

GET `/api/plan` schema شامل plan جاری، FeatureMap حساب، matrix هر plan، plans، upgradeRequest و endsAt است. query `?locked=<feature>` از redirectهای feature gate خوانده می‌شود و کارت هشدار label و پلن فعلی را نشان می‌دهد. کارت‌های پلن نام/tag/قیمت/قیمت قدیم/تعداد قابلیت غیر-no و دکمه request دارند. پلن جاری disabled؛ پلنی که درخواست در انتظارش است نیز disabled و برچسب درخواست ثبت شده.

پایین صفحه matrix همه FEATUREها را در GROUPS می‌چیند؛ هر plan ستون `yes/no/custom` دارد و ستون حساب، entitlement مؤثر همان user را نمایش می‌دهد. custom به badge اختصاصی، no به قفل/X، yes به check تبدیل می‌شود. POST `/api/plan {plan}` فقط درخواست ارتقا می‌سازد؛ toast می‌گوید تأیید ادمین لازم است و دسترسی فوری فرض نمی‌شود. تاریخ پایین UI فعلاً `formatDate(new Date())` است، آن را به تاریخ پایان قرارداد تعبیر نکن.

**پذیرش:** locked query ناشناخته/معتبر، account feature disabled، درخواست pending، پلان فعلی، data loading و POST fail؛ هیچ client-side تغییر entitlement.

## مرجع بازسازی

برای جزئیات دقیق فیلدها، ترتیب کنترل‌ها، پیام‌های فارسی و قرارداد typeها، فایل منبع بالا را همراه API route متناظر در `src/app/api` بخوان. این راهنما رفتار را مشخص می‌کند و جایگزین بررسی source-of-truth نیست.
