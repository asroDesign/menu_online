# تأمین‌کنندگان

> مشخصات بازسازی ماژول `suppliers` برای عامل پیاده‌سازی. این سند رفتار و قرارداد ماژول فعلی را خلاصه می‌کند؛ اگر اختلافی با کد زنده وجود داشت، کد و API فعلی منبع حقیقت هستند.

## جایگاه و دسترسی

- مسیر پنل: `/dashboard/suppliers`
- کامپوننت/منبع فعلی: `src/modules/suppliers.tsx — Suppliers`
- entitlement تعرفه: `inventory + accounting`
- هدف: ثبت تأمین‌کننده، مانده حساب و گردش خرید/پرداخت.

## رابط و جریان کار

فهرست CRUD تأمین‌کنندگان با جست‌وجو و جمع بدهی؛ نمایش صورت‌حساب یک تأمین‌کننده در modal شامل خریدها و پرداخت‌ها؛ ثبت پرداخت با مبلغ، منبع پرداخت، تاریخ شمسی و توضیح؛ چاپ صورت‌حساب.

## داده و API

ResourcePage روی /api/r/suppliers؛ GET /api/r/suppliers/:id برای statement؛ POST /api/r/supplierpay؛ سند چاپی /print/doc/:id.

## قواعدی که بازنویسی باید حفظ کند

پرداخت بدهی نباید موجودی انبار را تغییر دهد؛ مبلغ و منبع باید معتبر باشند؛ تاریخ در UI شمسی و ذخیره‌سازی مطابق قرارداد API؛ جمع مانده از تراکنش‌ها محاسبه شود.

- وضعیت‌های loading، خطا، داده خالی و موفقیت را جدا و قابل فهم نشان بده؛ خطا را با امکان تلاش مجدد مدیریت کن.
- رابط فارسی و RTL، ارقام فارسی، پول تومان، و تاریخ‌های شمسی را مطابق ابزارهای مشترک پروژه نمایش بده.
- layout را برای موبایل/تبلت/دسکتاپ بازسازی کن؛ فرم‌ها و جدول‌ها در عرض کم قابل استفاده بمانند و اکشن اصلی از دسترس خارج نشود.
- عملیات را با componentهای مشترک `src/components/ui.tsx`, `src/components/resource-page.tsx` و `src/lib/api.ts` هم‌راستا کن؛ بعد از mutation فهرست/cache را تازه کن.
- tenant isolation، احراز هویت، entitlement و نقش باید سمت API نیز enforce شود؛ مخفی کردن دکمه به‌تنهایی مجوز نیست.

## مشخصات سطح پیاده‌سازی

### مدل و فهرست

Supplier شامل `name`, `contactPerson`, `phone`, `address`, `taxId`, `bankInfo`, `note`, `isActive` و مقادیر تزئینی/محاسباتی `purchased`, `paid`, `balance` است. فهرست بالای صفحه سه KPI دارد: جمع بدهی مثبت همه فروشندگان، تعداد کل و تعداد مانده‌دار. جست‌وجو روی name/phone و checkbox «فقط دارای بدهی» اعمال می‌شود. ستون‌ها خرید نسیه، پرداخت‌شده و مانده را کنار اطلاعات تماس نشان می‌دهند؛ دکمه چاپ گزارش بدهی از `window.print()` استفاده می‌کند.

### جریان‌ها

فرم افزودن/ویرایش فیلدهای تماس فروشنده و tax ID/bank info/note را دارد. action صورت‌حساب، header فروشنده و ردیف‌های سند با شماره، تاریخ جلالی، description، debit، credit و balance را در modal نشان می‌دهد و سند مرتبط را به `/print/doc/:id` وصل می‌کند. پرداخت با amount، منبع `cash|bank`، تاریخ شمسی و note ثبت می‌شود؛ پاسخ شماره سند می‌دهد و لیست reload می‌شود. اگر feature accounting نباشد یا نقش کاربر مجاز نباشد، اکشن پرداخت باید مخفی/غیرفعال باشد (`canPay` در UI: owner/manager/accountant + accounting).

**پذیرش:** نمایش فروشنده با balance صفر، فقط بدهکارها، خطای حذف/پرداخت، تاریخ شمسی، چاپ بدون toolbar، ثبت خرید نسیه از گردش انبار و reconcile بدهی از ledger را پوشش بده. ثبت پرداخت نباید stock را تغییر دهد.

## مرجع بازسازی

برای جزئیات دقیق فیلدها، ترتیب کنترل‌ها، پیام‌های فارسی و قرارداد typeها، فایل منبع بالا را همراه API route متناظر در `src/app/api` بخوان. این راهنما رفتار را مشخص می‌کند و جایگزین بررسی source-of-truth نیست.
