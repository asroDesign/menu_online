# دسته‌بندی منو

> راهنمای بازسازی عامل برای صفحه‌ی ثابت داشبورد.

- مسیر: `/dashboard/categories`
- منبع: `src/app/dashboard/categories/page.tsx`
- هدف: مدیریت ساختار گروه‌بندی کاتالوگ و ترتیب نمایش.

## رابط و رفتار

فهرست مرتب‌شده، ایجاد/ویرایش نام و وضعیت فعال، تغییر ترتیب sortOrder، تعداد/محصولات وابسته و حذف با هشدار اینکه محصولات بدون دسته می‌مانند.

## API و داده

GET/CRUD /api/categories؛ GET /api/products.

## الزامات بازنویسی

دسته غیرفعال در منوی عمومی پنهان؛ ترتیب پایدار؛ حذف دسته نباید محصول‌ها را بی‌صدا حذف کند.

این صفحه باید با shell مشترک داشبورد و اصول UI/RTL در `README.md` این پوشه هماهنگ باشد. برای schema کامل، منبع و routeهای API ذکرشده را بخوان.

## مشخصات سطح پیاده‌سازی

### مدل و تعامل

هر ردیف دسته حداقل `id`, `name`, `emoji`, `sortOrder`, `isActive` دارد. صفحه category و product را جداگانه می‌خواند تا تعداد کالاهای وابسته را محاسبه کند. مرتب‌سازی اولیه براساس `sortOrder` و سپس `id` است. ایجاد نام trim‌شده، نماد، `sortOrder` برابر شمار دسته‌های فعلی و `isActive=true` می‌فرستد؛ ویرایش فقط نام و نماد را تغییر می‌دهد. فعال‌سازی از Switch و ترتیب از دو کنترل بالا/پایین انجام می‌شود؛ حرکت باید هر دو همسایه را به‌روز کند.

فرم نام اجباری است، کلید Enter ذخیره می‌کند. حذف با تأیید می‌گوید چند محصول بعد از حذف بدون دسته می‌مانند؛ حذف پس از موفقیت فهرست محصول را دوباره بارگیری می‌کند. وضعیت loading، error/retry و empty با CTA ساخت اولین دسته لازم است.

### قواعد منو و بازسازی

ترتیب ذخیره‌شده ترتیب نمایش عمومی است؛ جابه‌جایی باید روی ترتیب مرتب‌شده اعمال شود و دکمه اولین/آخرین مورد disabled باشد. غیرفعال‌کردن یک دسته، خود محصولات را حذف یا غیرفعال نمی‌کند، اما دسته نباید در منوی مشتری به‌عنوان گروه فعال ظاهر شود. دسته بدون محصول هم معتبر است. APIهای `GET/POST /api/categories` و `PATCH/DELETE /api/categories/:id` منبع نهایی‌اند؛ پیش از ادغام دوباره، رفتار حذف محصول‌های وابسته را در route بررسی کن. در موبایل نام truncate نشود به‌نحوی که تنها کنش‌های ردیف از دست بروند.
