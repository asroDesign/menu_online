# دسته‌بندی منو

> راهنمای بازسازی عامل برای صفحه‌ی ثابت داشبورد.

- مسیر: `/dashboard/categories`
- منبع: `src/app/dashboard/categories/page.tsx`
- هدف: مدیریت ساختار گروه‌بندی کاتالوگ و ترتیب نمایش.

## رابط و رفتار

صفحه از `PageHeader` مشترک داشبورد برای عنوان، تعداد دسته‌ها، جستجو و CTAهای استاندارد استفاده می‌کند؛ زیر آن کارت جدول با ستون‌های تصویر، عنوان، تعداد محصولات، ردیف نمایش، وضعیت و مدیریت قرار دارد و شمار ردیف‌ها در کارت جداگانه‌ای پایین جدول می‌آید. جدول در ارتفاع محدود اسکرول عمودی و در نمایشگر باریک اسکرول افقی دارد؛ سرستون هنگام اسکرول ثابت می‌ماند. تصویر خالی با قاب خط‌چین نشان داده می‌شود و تصویر آپلودشده جایگزین آن است.

فرم ایجاد شامل نام، والد، تصویر و ترتیب است. فرم ویرایش همین موارد را به‌علاوه توضیحات و وضعیت فعال دارد. تصویر از ImageUpload و API بارگذاری موجود استفاده می‌کند. افزودن گروهی نام‌های واردشده در خطوط جداگانه را می‌سازد، نام‌های خالی/تکراری را رد می‌کند و برای دسته‌های تازه آیکن پیش‌فرض و ترتیب انتهایی می‌گذارد. حذف با تأیید انجام می‌شود و تعداد محصولاتی که بدون دسته می‌مانند اعلام می‌شود.

ساختار دسته اکنون والد اختیاری، توضیحات و URL تصویر را ذخیره می‌کند. API والد را فقط در tenant جاری می‌پذیرد و انتخاب خود دسته یا زیر‌دستهٔ خودش را به‌دلیل ایجاد چرخه رد می‌کند. گزینه‌های والد در UI نیز خود دسته و همهٔ فرزندان آن را پنهان می‌کنند. Migration `0039_category_management_fields.sql` ستون‌ها را با default سازگار به جدول موجود اضافه می‌کند؛ rollback آن در فایل `.down.sql` است.

## API و داده

GET/CRUD /api/categories؛ GET /api/products.

## الزامات بازنویسی

دسته غیرفعال در منوی عمومی پنهان؛ ترتیب پایدار؛ حذف دسته نباید محصول‌ها را بی‌صدا حذف کند.

این صفحه باید با shell مشترک داشبورد و اصول UI/RTL در `README.md` این پوشه هماهنگ باشد. برای schema کامل، منبع و routeهای API ذکرشده را بخوان.

## مشخصات سطح پیاده‌سازی

### مدل و تعامل

هر ردیف `id`, `businessId`, `name`, `parentCategoryId`, `description`, `emoji`, `imageUrl`, `sortOrder`, `isActive` دارد. صفحه category و product را جداگانه می‌خواند تا شمار محصولات وابسته را محاسبه کند. API CRUD از `makeCrud` استفاده می‌کند و برای والد، گراف دسته‌های همان کسب‌وکار را به `categoryParentError` می‌دهد. ترتیب نمایشی یک‌مبنا در فرم به `sortOrder` صفرمبنا در DB تبدیل می‌شود؛ ذخیرهٔ تغییر ترتیب سایر ردیف‌های لازم را نیز به ترتیب انجام می‌دهد. افزودن گروهی روی خط‌های یکتا پشت سر هم create می‌زند و اگر یک درخواست شکست بخورد، ساخته‌های قبلی را حفظ و فهرست را دوباره بارگیری می‌کند.

فرم نام اجباری و حداکثر ۶۰ نویسه است؛ توضیحات حداکثر ۵۰۰ نویسه است. فرزندان یک دسته به‌عنوان والد آن دسته قابل انتخاب نیستند. حذف با تأیید می‌گوید چند محصول بعد از حذف بدون دسته می‌مانند؛ پس از موفقیت دادهٔ محصول و دسته بارگیری مجدد می‌شود. وضعیت loading، error/retry و empty با CTA ساخت اولین دسته لازم است.

### قواعد منو و بازسازی

ترتیب ذخیره‌شده ترتیب منو است؛ غیرفعال‌کردن دسته محصولات را حذف نمی‌کند. دسته بدون محصول معتبر است. APIهای `GET/POST /api/categories` و `PATCH/DELETE /api/categories/:id` منبع نهایی‌اند؛ مهاجرت DB باید پیش از اجرای نسخهٔ تازه اعمال شود. FK والد به همان جدول است و در حذف والد، ارجاع فرزند به `NULL` تبدیل می‌شود.

### اعتبارسنجی و تطبیق — ۲۰۲۶-۱۰-۲۱

نمونه و نسخهٔ محلی در Chrome در viewport یکسان مقایسه شدند؛ ترتیب کنترل‌ها، کارت سربرگ/جدول/جمع کل، ارتفاع جدول، placeholder تصویر، رنگ دکمهٔ اصلی و نشان وضعیت بر اساس نمونه تنظیم شدند. migration `0039` روی دیتابیس محلی به‌صورت تراکنشی اعمال شد و پس از بارگیری مجدد، جدول ۸ دسته را بدون خطای API نمایش داد. در محیط‌های دیگر باید migration را پیش از اجرای UI اعمال کرد؛ rollback فقط ستون‌های افزوده‌شده و index را حذف می‌کند.


## بهینه‌سازی مودال‌های دسته‌بندی — ۲۰۲۶-۱۰-۲۱

- فرم ایجاد و ویرایش با سربرگ توضیح‌دار، حذف padding اضافهٔ پنجره، والد و ترتیب در دو ستون دسکتاپ/یک ستون موبایل، آپلود تصویر کوچک‌تر و ردیف مستقل وضعیت نمایش بازطراحی شد. بدنه در ارتفاع محدود اسکرول می‌شود و دکمه‌های پایین ثابت می‌مانند.
- Modal پراپ اختیاری `description` دریافت کرد؛ ظاهر بدون padding اضافه فقط برای استفاده‌کنندگان این پراپ اعمال می‌شود. ImageUpload پراپ اختیاری `compact` با پیش‌فرض false دارد تا چیدمان سایر فرم‌ها حفظ شود.
- حالت ذخیرهٔ دسته loading دارد، فرم و انصراف غیرفعال می‌شوند و Escape/بستن پس‌زمینه تا پایان درخواست عمل نمی‌کند. قفل ارسال تکراری قبلی حفظ شد؛ افزودن گروهی نیز در زمان درخواست بسته نمی‌شود. selectorهای تور حفظ شدند.
- راهنمای افزودن گروهی در کادر آبی و تأیید حذف در کادر هشدار با نام دسته و تعداد محصولات نمایش داده می‌شوند؛ API، schema و داده‌ها تغییر نکردند.
- اعتبارسنجی: typecheck بدون incremental، ESLint سه فایل و ۵۷ تست security-regressions/onboarding-tour موفق. مودال ایجاد و ویرایش در Chrome دسکتاپ بصری بررسی شد؛ داده‌ای ذخیره یا حذف نشد. آزمون مرورگر موبایل انجام نشد.


### یادداشت تکمیلی مودال — ۲۰۲۶-۱۰-۲۱

مودال‌های این صفحه از Modal استاندارد با ظاهر عمومی سایت استفاده می‌کنند. اندازه، focus trap و بازگرداندن فوکوس در `ui-components.md` در همین پوشه مستند است؛ در این صفحه فرم فشرده، تصویر compact، حالت pending و محافظت از بستن هنگام ذخیره افزوده شده است. پیاده‌سازی سراسری ظاهر Modal که پس از بهینه‌سازی اولیهٔ این صفحه انجام شد، جایگزین شرط قبلی وابسته به description شده و اکنون برای همهٔ استفاده‌کنندگان Modal فعال است.


## هم‌ترازی با طراحی مشترک پنل — ۲۰۲۶-۱۰-۲۱

سربرگ از `PageHeader` مشترک، CTAها از `Button`، عملیات ردیف از `IconButton`، فیلدهای متنی از `Input`/`Textarea`، وضعیت از `Badge` و سطح‌ها از `Card` استفاده می‌کنند. رنگ‌های hard-code حذف شده و tokenهای تم پایه به کار می‌روند. جدول و ستون‌های ویژگی حفظ شده‌اند؛ اکشن‌های سربرگ در عرض کم wrap می‌شوند.

## ایجاد دستهٔ پایه در Windows آفلاین

تب منوی محلی Windows امکان ثبت دسته با نام، توضیح، وضعیت فعال و ترتیب را با PIN مدیر محلی فراهم می‌کند. دسته تا همگام‌سازی و دریافت snapshot جدید به شناسهٔ سرور تبدیل نمی‌شود؛ بنابراین محصول تازه در همان زمان نمی‌تواند به دستهٔ تازه متصل شود و دستهٔ قابل انتخاب محصول فقط از دسته‌های فعالِ موجود در snapshot است. ساخت دسته و command ledger در یک تراکنش سرور ثبت می‌شوند و UUID فرمان از ایجاد دوباره در retry جلوگیری می‌کند. والد، تصویر، حذف، ترتیب گروهی و سایر عملیات دسته‌بندی همچنان آنلاین‌اند. جزئیات در راهنمای پنل کامل آفلاین و گزارش توسعهٔ offline-menu-creation آمده است.
