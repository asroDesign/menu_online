# راهنمای پنل بله (اتصال فعلاً غیرفعال)

> مشخصات بازسازی ماژول `bale` برای عامل پیاده‌سازی. این سند رفتار و قرارداد ماژول فعلی را خلاصه می‌کند؛ اگر اختلافی با کد زنده وجود داشت، کد و API فعلی منبع حقیقت هستند.

## جایگاه و دسترسی

- مسیر پنل: `/dashboard/bale`
- کامپوننت/منبع فعلی: `src/modules/growth-b.tsx — export function Bale()`
- entitlement تعرفه: `bale`
- هدف فعلی: توضیح محدودیت‌های اتصال بله و هدایت مدیر به پنل پیامک؛ ارسال کمپین در این صفحه پیاده‌سازی نشده است.

## رابط و جریان کار

یک کارت اطلاعاتی است: توضیح نیاز ربات به start و `chat_id` ذخیره‌شده، تصریح اینکه ارسال واقعی وصل نیست و کمپین ساختگی ثبت نمی‌شود، و لینک مستقیم `/dashboard/sms`. فرم کمپین، تاریخچه ارسال و تنظیم ربات در این component وجود ندارد.

## داده و API

خود `Bale()` endpointی را صدا نمی‌زند. handler عمومی `Messaging({channel:"bale"})` در همین فایل تعریف شده، اما `Bale()` از آن استفاده نمی‌کند؛ handler `POST /api/r/bale` هم به‌صراحت درخواست ارسال را با 400 رد می‌کند. بنابراین API موجود را با UI قابل استفاده اشتباه نگیر.

- وضعیت‌های loading، خطا، داده خالی و موفقیت را جدا و قابل فهم نشان بده؛ خطا را با امکان تلاش مجدد مدیریت کن.
- رابط فارسی و RTL، ارقام فارسی، پول تومان، و تاریخ‌های شمسی را مطابق ابزارهای مشترک پروژه نمایش بده.
- layout را برای موبایل/تبلت/دسکتاپ بازسازی کن؛ فرم‌ها و جدول‌ها در عرض کم قابل استفاده بمانند و اکشن اصلی از دسترس خارج نشود.
- عملیات را با componentهای مشترک `src/components/ui.tsx`, `src/components/resource-page.tsx` و `src/lib/api.ts` هم‌راستا کن؛ بعد از mutation فهرست/cache را تازه کن.
- tenant isolation، احراز هویت، entitlement و نقش باید سمت API نیز enforce شود؛ مخفی کردن دکمه به‌تنهایی مجوز نیست.

## مشخصات واقعی نسخه فعلی

این مسیر فعلاً **صفحه ارسال کمپین نیست**. `Bale` در `src/modules/growth-b.tsx` کارت توضیحی دارد: ربات بله تنها به کاربری می‌تواند پیام بدهد که قبلاً ربات را start کرده و `chat_id` او ذخیره باشد؛ ارسال بر اساس شماره موبایل شدنی نیست. UI صریحاً می‌گوید اتصال واقعی وجود ندارد و هیچ ارسال یا کمپین ساختگی ثبت نمی‌شود؛ یک دکمه به `/dashboard/sms` می‌برد تا اطلاع‌رسانی از پنل پیامک انجام شود.

این صفحه را با component `Messaging({channel:"bale"})` اشتباه نکن: آن generic component فقط برای channelهای sms/bale تعریف شده، اما export عمومی `Bale()` در حال حاضر از آن استفاده نمی‌کند؛ handler `Messaging` در نمایش مسیر Bale mount نشده. بنابراین برای بازسازی رفتار فعلی، صفحه read-only informational با CTA پیامک بساز و endpoint ساختگی `/api/r/bale` اضافه نکن.

**پذیرش:** متن محدودیت chat_id، نبود ارسال واقعی، نبود تاریخچه جعلی و لینک رفتن به SMS باید آشکار باشند. دسترسی route همچنان entitlement `bale` دارد و `MODULE_ONLY.bale` آن را برای owner/manager محدود می‌کند.

## مرجع بازسازی

برای جزئیات دقیق فیلدها، ترتیب کنترل‌ها، پیام‌های فارسی و قرارداد typeها، فایل منبع بالا را همراه API route متناظر در `src/app/api` بخوان. این راهنما رفتار را مشخص می‌کند و جایگزین بررسی source-of-truth نیست.
