# کنترل موجودی

> مشخصات بازسازی ماژول `stock-control` برای عامل پیاده‌سازی. این سند رفتار و قرارداد ماژول فعلی را خلاصه می‌کند؛ اگر اختلافی با کد زنده وجود داشت، کد و API فعلی منبع حقیقت هستند.

## جایگاه و دسترسی

- مسیر پنل: `/dashboard/stock-control`
- کامپوننت/منبع فعلی: `src/modules/inventory.tsx — StockControl`
- entitlement تعرفه: `stock_control`
- هدف: شمارش فیزیکی و تطبیق موجودی با سیستم و پیشنهاد خرید.

## رابط و جریان کار

پنل اقلام زیر حداقل با مقدار پیشنهادی خرید ≈ max(0,2*min-stock) و ارزش تخمینی؛ جدول موجودی سیستمی، ورودی شمارش واقعی، اختلاف +/- و ثبت شمارش.

## داده و API

GET /api/r/items؛ POST /api/r/stockcount {itemId,counted}.

## قواعدی که بازنویسی باید حفظ کند

ثبت شمارش باید اختلاف را به movement تعدیل تبدیل کند، نه overwrite بی‌ردپا؛ مقدار صفر مجاز؛ ورودی منفی/غیرعددی رد شود.

- وضعیت‌های loading، خطا، داده خالی و موفقیت را جدا و قابل فهم نشان بده؛ خطا را با امکان تلاش مجدد مدیریت کن.
- رابط فارسی و RTL، ارقام فارسی، پول تومان، و تاریخ‌های شمسی را مطابق ابزارهای مشترک پروژه نمایش بده.
- layout را برای موبایل/تبلت/دسکتاپ بازسازی کن؛ فرم‌ها و جدول‌ها در عرض کم قابل استفاده بمانند و اکشن اصلی از دسترس خارج نشود.
- عملیات را با componentهای مشترک `src/components/ui.tsx`, `src/components/resource-page.tsx` و `src/lib/api.ts` هم‌راستا کن؛ بعد از mutation فهرست/cache را تازه کن.
- tenant isolation، احراز هویت، entitlement و نقش باید سمت API نیز enforce شود؛ مخفی کردن دکمه به‌تنهایی مجوز نیست.

## مشخصات سطح پیاده‌سازی

تمام items از `/api/r/items` فهرست می‌شوند. شمارش موجودی واقعی per item در input decimal موقت نگهداری می‌شود؛ اختلاف=`counted-stock`, مثبت سبز، منفی قرمز، صفر خاکستری. CTA فقط برای اختلاف non-zero معتبر فعال و action POST `/api/r/stockcount {itemId,counted}` است؛ موفقیت draft count همان قلم را پاک و item collection را reload می‌کند.

کارت هشدار only items `stock<=minStock`; برای هر قلم پیشنهاد خرید `max(0,2*minStock-stock)` و هزینه تقریبی با `costPerUnit`. صفحه اگر هیچ item ندارد به `/dashboard/inventory` راهنمایی می‌دهد؛ خطای فهرست و loading جداست.

**قواعد:** count=0 ممکن است معتبر باشد؛ مقدار خالی با صفر یکی نیست؛ رقم فارسی/decimal normalize؛ در API اختلاف باید movement `adjust` ایجاد کند تا trail حفظ شود، نه اینکه مقدار stock بی‌سند overwrite شود.

**پذیرش:** شمارش بدون اختلاف disabled، شمارش صفر، منفی invalid، ثبت موفق، خطای API و reload؛ shortage KPI و پیشنهاد خرید را verify کن.

## مرجع بازسازی

برای جزئیات دقیق فیلدها، ترتیب کنترل‌ها، پیام‌های فارسی و قرارداد typeها، فایل منبع بالا را همراه API route متناظر در `src/app/api` بخوان. این راهنما رفتار را مشخص می‌کند و جایگزین بررسی source-of-truth نیست.
