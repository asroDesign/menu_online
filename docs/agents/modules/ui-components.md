# کامپوننت‌های رابط مشترک MenuPeak

> راهنمای بازسازی عامل برای کنترل‌های مشترک فرم و پنجره‌های محاوره‌ای.

- منبع اصلی: `src/components/ui.tsx`
- استفاده‌کنندگان نمونه: فرم‌های داشبورد و مدیر سامانه، ثبت سفارش، انبار، دسته‌بندی، محصولات، کاربران و تنظیمات.
- تصاویر/آپلود: `src/components/image-upload.tsx`؛ این بخش مستقل است و در بعضی فرم‌ها compact می‌شود.

## اجزا

### Modal

ورودی‌ها: `open`, `onClose`, `title`, اختیاری `description`, `children`, اختیاری `footer`, و `size` از `sm | md | lg | xl`. پنجره در portal زیر `document.body` قرار می‌گیرد. از کامپوننت برای فرم‌ها، مرور جزئیات، انتخاب‌ها و محاوره‌های تأیید استفاده می‌شود.

ظاهر مشترک یک سربرگ با خط رنگی برند و دکمهٔ بستن، پنل سفید با گوشه‌های گرد، بدنهٔ قابل اسکرول، و footer ثابت دارد. در موبایل پنجره از پایین به شکل sheet باز می‌شود، عرض صفحه را می‌گیرد و padding انتهایی safe-area را رعایت می‌کند؛ در نمایش بزرگ وسط‌چین است. حداکثر ارتفاع ۹۲dvh یا ۵۶rem است. کلاس `modal-box` باید `!p-0` داشته باشد چون padding داخلی DaisyUI با padding بخش‌های header/body/footer تداخل می‌کند.

`description` اختیاری است و متن کوتاه راهنما زیر عنوان می‌آورد. اندازهٔ `sm` فرم کوتاه، `md` فرم معمول، `lg` فرم بزرگ چندبخشی، و `xl` جدول/فرم گسترده است. برای فرم بلند، محتوا را در خود بدنه قرار دهید تا اسکرول فقط داخل آن باشد؛ CTA را در `footer` بدهید تا ثابت بماند. Footer به‌طور پیش‌فرض دکمه‌ها را راست‌چین و wrap می‌کند. در فرم بسیار فشرده می‌توان footer را به‌صورت یک فرزند تمام‌عرض override کرد.

### دسترسی و رفتار

- با بازشدن، body scroll قفل می‌شود و بعد از بستن مقدار پیشین آن برمی‌گردد.
- کنترل دارای `autoFocus` اولویت فوکوس دارد؛ در غیر این صورت نخستین کنترل قابل استفاده فوکوس می‌شود. Tab و Shift+Tab داخل پنجره می‌مانند. Escape و کلیک backdrop، `onClose` را اجرا می‌کنند. فوکوس پس از بستن به عنصر فعال قبلی بازمی‌گردد.
- `aria-modal`, `role=dialog` و `aria-label=title` برای صفحه‌خوان فراهم است. عناصر کنترلی باید label دسترس‌پذیر داشته باشند. دکمه بستن aria-label فارسی دارد.
- تغییر state والد در زمان ذخیره می‌تواند بستن را متوقف کند: callback `onClose` در parent باید busy state را بررسی کند؛ دکمه‌های footer نیز هنگام درخواست loading/disabled شوند. خود Modal از نتیجهٔ API اطلاع ندارد.
- اگر هم‌زمان مودال دیگری باز است، بستن باید در parent مدیریت شود. از بازکردن چند Modal مستقل روی هم پرهیز کنید.

### ConfirmDialog

`ConfirmDialog` از `Modal` با اندازه `sm` استفاده می‌کند؛ عنوان و پیام می‌گیرد و CTAهای انصراف/تأیید می‌سازد. اگر عملیات async است، مدیریت `busy`, نگه‌داشتن پنجره تا پاسخ و خطا باید در parent باشد؛ ConfirmDialog عمومی Promise را منتظر نمی‌ماند. حذف‌های برگشت‌پذیر هم باید نام هدف و پیامد را در message توضیح دهند.

## بازسازی overlayهای پیشین

فرم‌های modal سفارشی باید به Modal مشترک منتقل شوند، تا رفتار responsive، فاصله‌ها، focus trap و خروج صفحه‌کلید هماهنگ بماند. موردهای صفحهٔ محصول/دسته و فرم محتوای مدیر به همین الگو تبدیل شده‌اند. Drawer منو و صفحهٔ کامل کیوسک پنجرهٔ محاوره‌ای فرم نیستند و الگوی ویژه دارند.

## ثبت این تغییر

در تاریخ ۲۰۲۶-۱۰-۲۱ ظاهر مشترک برای همهٔ استفاده‌کنندگان Modal یکسان شد. قبلاً بعضی مودال‌ها padding پیش‌فرض DaisyUI را با padding داخلی جمع می‌کردند و چند فرم overlay مستقل ظاهر جدا داشتند. این تغییر route، API یا مدل داده را عوض نمی‌کند.
