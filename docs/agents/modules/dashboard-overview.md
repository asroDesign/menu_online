# داشبورد اصلی

> راهنمای بازسازی عامل برای صفحه‌ی ثابت داشبورد.

- مسیر: `/dashboard`
- منبع: `src/app/dashboard/page.tsx + src/modules/overview.tsx`
- هدف: صفحه خلاصه برای نقش‌های مدیریتی؛ صفحه سرور authentication را می‌خواند و نقش‌هایی که خانه دیگری دارند redirect می‌شوند. Overview هر ۱۵ ثانیه /api/stats را در صورت visible بودن tab تازه می‌کند.

## رابط و رفتار

کارت فروش امروز/هفته و تغییر نسبت به دوره قبل، میانگین فاکتور، نمودار فروش، نمودار روزانه بازدید منو، محصولات پرفروش، تعداد سفارش بر اساس وضعیت، تعداد میز/محصول و سفارش‌های اخیر. CTA به ثبت سفارش و جزئیات ماژول‌ها براساس entitlement لینک می‌دهد.

## API و داده

GET /api/stats؛ برای role redirect از ROLE_HOME و برای entitlement از useFeatures.

## الزامات بازنویسی

داده آماری از سرور؛ polling در unmount پاک شود و tab hidden درخواست نسازد؛ نقش از getAuth بررسی شود.

این صفحه باید با shell مشترک داشبورد و اصول UI/RTL در `README.md` این پوشه هماهنگ باشد. برای schema کامل، منبع و routeهای API ذکرشده را بخوان.

## مشخصات سطح پیاده‌سازی

### داده و محاسبه

- منبع داده `GET /api/stats` است. مدل `Stats` شامل `today` (فروش، تعداد سفارش، میانگین فاکتور، تغییر فروش نسبت به دیروز)، `week` (فروش/سفارش/درصد تغییر)، سری فروش روزانه، `menuViews` با ۱۴ نقطهٔ روزانه، کالاهای پرفروش، شمار سفارش‌ها بر اساس وضعیت، سفارش‌های فعال، میزهای اشغال/کل، شمار محصول‌ها و سفارش‌های اخیر است.
- نمودار، هفت روز اخیر را نشان می‌دهد؛ هر نقطه تاریخ، درآمد و تعداد سفارش دارد. کارت پرفروش‌ها بازه ۱۴ روزه را نمایش می‌دهد. «فروش» از پاسخ API می‌آید و در UI دوباره از روی سفارش‌های اخیر جمع زده نمی‌شود.
- نمودار «بازدید منو» جمع رویدادهای `menu_view` از `menu_events` را برای هر روز تقویمی در ۱۴ روز اخیر نمایش می‌دهد. SQL روز را با `Asia/Tehran` گروه‌بندی و فقط رویدادهای `business.id` جاری را می‌خواند. روزهای بدون رویداد در `src/lib/menu-views-core.ts` با صفر پر می‌شوند. شمارش، تعداد رویداد است و بازدید یکتا محسوب نمی‌شود؛ هر بار بازشدن منوی عمومی که event ثبت کند، شمرده می‌شود. بازدید منوی نمایشی از این مسیر عمومی به عنوان بازدید کسب‌وکار ثبت نمی‌شود.
- نمودار بازدید با میله‌های واکنش‌گرا، برچسب روز شمسی، راهنمای tooltip شامل تاریخ/شمارش، مجموع دوره و متن قابل‌دسترس برای screen reader نمایش داده می‌شود. داده‌های روزانه هر ۱۵ ثانیه همراه سایر آمار تازه می‌شوند.
- `activeCount` و `tables.occupied/total` شاخص عملیات جاری‌اند؛ میانگین فاکتور امروز فقط براساس سفارش‌های پرداخت‌شده محاسبه می‌شود. مقادیر درصدی ممکن است null باشند و در این صورت Delta نباید نمایش داده شود.

### ترتیب و حالات صفحه

1. در ابتدا کارت‌های Skeleton نمایش داده شوند؛ خطای بار اول تمام صفحه را با `ErrorState` و امکان بارگیری مجدد جایگزین می‌کند.
2. اگر هنوز محصولی وجود ندارد، EmptyState راه ساخت دسته‌بندی را ارائه می‌کند؛ داشبورد خالی نباید نمودار ساختگی بسازد.
3. در حالت داده‌دار، چهار KPI، نمودار فروش هفت‌روزه، نمودار بازدید منوی ۱۴روزه، فهرست پرفروش‌ها و سفارش‌های اخیر نمایش داده می‌شوند. اگر بازدیدی ثبت نشده باشد، مجموع صفر و پیام خالی نشان داده می‌شود و میله‌های داده‌نداشته به‌عنوان بازدید مثبت جعل نمی‌شوند. فهرست اخیر حداقل شماره، میز/نوع سفارش، تعداد اقلام، زمان نسبی، وضعیت و مبلغ را دارد.
4. CTA ثبت سفارش فقط به مسیر مجاز براساس entitlement می‌رود؛ لینک «مشاهده همه» به سفارش‌هاست.

### به‌روزرسانی و پذیرش

صفحه هنگام mount یک بار می‌خواند و هر ۱۵ ثانیه در صورتی که tab مخفی نباشد تازه‌سازی می‌کند؛ interval در unmount پاک شود. شکست polling پس از بار اول داده قبلی را پاک نکند و باعث چشمک خطا نشود. در موبایل KPIها تک‌ستونی، سپس دو ستونی شوند؛ نمودارهای فروش و بازدید بدون overflow افقی قابل خواندن باشند. اعداد با formatterهای مشترک و تاریخ‌های نمودار بازدید با تقویم شمسی عرضه شوند.

### مسیر داده و کنترل دسترسی بازدید

- رویداد منو توسط `src/components/menu-client.tsx` با `trackMenuEvent(slug, "menu_view")` به `POST /api/public/:slug/events` می‌رود؛ route عمومی نرخ درخواست را محدود و کسب‌وکار را از slug معتبر پیدا می‌کند.
- `GET /api/stats` از `withAuth` و guard نقش مدیریتی/حسابدار استفاده می‌کند. query بازدید در سرور با `business.id` احرازشده محدود است؛ slug یا businessId از query کاربر برای تعیین tenant استفاده نمی‌شود.
- منبع شمارش همان `menu_events` است که قیف گزارش منو نیز از آن استفاده می‌کند. migration تازه یا نوشتن/افزایش شمارندهٔ جداگانه نیاز نیست.
- `tests/menu-views-dashboard.test.cjs` سری روزانه، تکمیل روزهای خالی، محدودهٔ tenant و قرارداد نمایش ۱۴روزه را بررسی می‌کند.
