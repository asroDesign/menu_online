# داشبورد اصلی

> راهنمای بازسازی عامل برای صفحه‌ی ثابت داشبورد.

- مسیر: `/dashboard`
- منبع: `src/app/dashboard/page.tsx + src/modules/overview.tsx`
- هدف: صفحه خلاصه برای نقش‌های مدیریتی؛ صفحه سرور authentication را می‌خواند و نقش‌هایی که خانه دیگری دارند redirect می‌شوند. Overview هر ۱۵ ثانیه /api/stats را در صورت visible بودن tab تازه می‌کند.

## رابط و رفتار

کارت فروش امروز/هفته و تغییر نسبت به دوره قبل، میانگین فاکتور، نمودار فروش، محصولات پرفروش، تعداد سفارش بر اساس وضعیت، تعداد میز/محصول و سفارش‌های اخیر. CTA به ثبت سفارش و جزئیات ماژول‌ها براساس entitlement لینک می‌دهد.

## API و داده

GET /api/stats؛ برای role redirect از ROLE_HOME و برای entitlement از useFeatures.

## الزامات بازنویسی

داده آماری از سرور؛ polling در unmount پاک شود و tab hidden درخواست نسازد؛ نقش از getAuth بررسی شود.

این صفحه باید با shell مشترک داشبورد و اصول UI/RTL در `README.md` این پوشه هماهنگ باشد. برای schema کامل، منبع و routeهای API ذکرشده را بخوان.

## مشخصات سطح پیاده‌سازی

### داده و محاسبه

- منبع داده `GET /api/stats` است. مدل `Stats` شامل `today` (فروش، تعداد سفارش، میانگین فاکتور، تغییر فروش نسبت به دیروز)، `week` (فروش/سفارش/درصد تغییر)، سری زمانی روزانه، کالاهای پرفروش، شمار سفارش‌ها بر اساس وضعیت، سفارش‌های فعال، میزهای اشغال/کل، شمار محصول‌ها و سفارش‌های اخیر است.
- نمودار، هفت روز اخیر را نشان می‌دهد؛ هر نقطه تاریخ، درآمد و تعداد سفارش دارد. کارت پرفروش‌ها بازه ۱۴ روزه را نمایش می‌دهد. «فروش» از پاسخ API می‌آید و در UI دوباره از روی سفارش‌های اخیر جمع زده نمی‌شود.
- `activeCount` و `tables.occupied/total` شاخص عملیات جاری‌اند؛ میانگین فاکتور امروز فقط براساس سفارش‌های پرداخت‌شده محاسبه می‌شود. مقادیر درصدی ممکن است null باشند و در این صورت Delta نباید نمایش داده شود.

### ترتیب و حالات صفحه

1. در ابتدا کارت‌های Skeleton نمایش داده شوند؛ خطای بار اول تمام صفحه را با `ErrorState` و امکان بارگیری مجدد جایگزین می‌کند.
2. اگر هنوز محصولی وجود ندارد، EmptyState راه ساخت دسته‌بندی را ارائه می‌کند؛ داشبورد خالی نباید نمودار ساختگی بسازد.
3. در حالت داده‌دار، چهار KPI، نمودار فروش، فهرست پرفروش‌ها و سفارش‌های اخیر نمایش داده می‌شوند. فهرست اخیر حداقل شماره، میز/نوع سفارش، تعداد اقلام، زمان نسبی، وضعیت و مبلغ را دارد.
4. CTA ثبت سفارش فقط به مسیر مجاز براساس entitlement می‌رود؛ لینک «مشاهده همه» به سفارش‌هاست.

### به‌روزرسانی و پذیرش

صفحه هنگام mount یک بار می‌خواند و هر ۱۵ ثانیه در صورتی که tab مخفی نباشد تازه‌سازی می‌کند؛ interval در unmount پاک شود. شکست polling پس از بار اول داده قبلی را پاک نکند و باعث چشمک خطا نشود. در موبایل KPIها تک‌ستونی، سپس دو ستونی شوند؛ نمودار با هفت ستون بدون overflow افقی قابل خواندن باشد. اعداد با `toFa`، مبلغ با `formatPrice` و زمان با formatter مشترک عرضه شوند.
