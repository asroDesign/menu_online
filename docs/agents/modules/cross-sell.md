# پیشنهاد مکمل

> مشخصات بازسازی ماژول `cross-sell` برای عامل پیاده‌سازی. این سند رفتار و قرارداد ماژول فعلی را خلاصه می‌کند؛ اگر اختلافی با کد زنده وجود داشت، کد و API فعلی منبع حقیقت هستند.

## جایگاه و دسترسی

- مسیر پنل: `/dashboard/cross-sell`
- کامپوننت/منبع فعلی: `src/modules/growth-b.tsx — CrossSell`
- entitlement تعرفه: `cross_sell`
- هدف: تعریف پیشنهاد دستی و پیشنهاد هوشمند غذا/نوشیدنی در سبد منوی عمومی؛ مسیر هوشمند بر اساس هم‌خریدهای گذشته و جفت‌سازی دستهٔ غذا/نوشیدنی کار می‌کند.

## رابط و جریان کار

انتخاب محصول مبدا و اقلام پیشنهادی، ویرایش/حذف rule؛ فهرست پیشنهادهای خودکار از آمار فروش؛ switch فعال بودن پیشنهاد خودکار.

## داده و API

GET /api/products؛ CRUD /api/r/crosssell؛ GET /api/r/crosssellauto؛ GET/PATCH /api/business settings.crossSellAuto.

## قواعدی که بازنویسی باید حفظ کند

محصولات باید متعلق به همان tenant و فعال باشند؛ پیشنهاد عمومی فقط محصول قابل سفارش را معرفی کند.

- وضعیت‌های loading، خطا، داده خالی و موفقیت را جدا و قابل فهم نشان بده؛ خطا را با امکان تلاش مجدد مدیریت کن.
- رابط فارسی و RTL، ارقام فارسی، پول تومان، و تاریخ‌های شمسی را مطابق ابزارهای مشترک پروژه نمایش بده.
- layout را برای موبایل/تبلت/دسکتاپ بازسازی کن؛ فرم‌ها و جدول‌ها در عرض کم قابل استفاده بمانند و اکشن اصلی از دسترس خارج نشود.
- عملیات را با componentهای مشترک `src/components/ui.tsx`, `src/components/resource-page.tsx` و `src/lib/api.ts` هم‌راستا کن؛ بعد از mutation فهرست/cache را تازه کن.
- tenant isolation، احراز هویت، entitlement و نقش باید سمت API نیز enforce شود؛ مخفی کردن دکمه به‌تنهایی مجوز نیست.

## مشخصات سطح پیاده‌سازی

دو مجموعه محصول و `crosssell` rules بارگیری می‌شوند. محصول جاری اولین محصول یا انتخاب کاربر است؛ ستون سمت چپ scroll می‌شود و badge تعداد ruleهای manual همان محصول را نشان می‌دهد. سمت راست همه محصولات غیر از مبدا کارت toggle هستند. کلیک یک پیشنهاد، اگر rule موجود باشد حذف وگرنه ایجاد می‌کند؛ محصول نباید خودش را پیشنهاد کند.

switch `crossSellAuto` از settings کسب‌وکار default true؛ save optimistic است اما در خطا rollback می‌شود. پایین صفحه حداکثر ۸ pair پرتکرار حاصل از `/api/r/crosssellauto` با count نمایش داده می‌شود. پیشنهاد دستی بر پیشنهاد خودکار اولویت دارد.

### منطق پیشنهاد غذا و نوشیدنی

- endpoint عمومی `GET /api/public/[slug]/recommendations?ids=...` فقط شناسه‌های مثبت را می‌پذیرد؛ جست‌وجوی محصول و دسته در سرور با `businessId` همان slug محدود است و خروجی فقط کالای قابل سفارش را دارد.
- ابتدا پیشنهادهای دستی با بالاترین اولویت رتبه‌بندی می‌شوند؛ سپس همراهی‌های ثبت‌شده در سفارش‌های قبلی، و در صورت روشن بودن `crossSellAuto` پیشنهاد جفت غذا/نوشیدنی تکمیل می‌شود.
- دسته‌بندی از نام محصول و نام دسته خوانده می‌شود؛ هنگامی که سبد شامل غذا و نوشیدنی نباشد، قلم‌های دستهٔ مکمل پیشنهاد می‌شوند. اگر هر دو نوع در سبد هستند یا نوع قلم قابل تشخیص نیست، الگوریتم جفت‌سازی حدسی پیشنهاد اضافه نمی‌کند.
- کارت مشتری دلیل هوشمند را با برچسب «نوشیدنی مناسب این غذا» یا «غذای همراه این نوشیدنی» نشان می‌دهد. منطق پیشنهاد در `src/lib/menu-recommendations.ts` مستقل و قابل آزمون است؛ این قابلیت AI/LLM نیست و به‌صورت قاعده‌محور و سابقه‌محور کار می‌کند.
- UI مدیر در `src/modules/growth-b.tsx` این رفتار و منبع تشخیص را توضیح می‌دهد؛ entitlement همان `cross_sell` می‌ماند و migration جدید لازم نیست.

**پذیرش:** کمتر از دو محصول empty؛ بدون auto data empty؛ toggle سریع و rollback؛ جلوگیری از self-suggest؛ تغییر global auto بدون پاک‌کردن قوانین دستی؛ پیشنهاد نوشیدنی برای غذای سبد، پیشنهاد غذا برای نوشیدنی سبد و عدم پیشنهاد جفت حدسی وقتی هر دو از قبل در سبد هستند.

## مرجع بازسازی

برای جزئیات دقیق فیلدها، ترتیب کنترل‌ها، پیام‌های فارسی و قرارداد typeها، فایل منبع بالا را همراه API route متناظر در `src/app/api` بخوان. این راهنما رفتار را مشخص می‌کند و جایگزین بررسی source-of-truth نیست.
