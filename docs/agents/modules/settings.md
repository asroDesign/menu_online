# تنظیمات کسب‌وکار

> راهنمای بازسازی عامل برای صفحه‌ی ثابت داشبورد.

- مسیر: `/dashboard/settings`
- منبع: `src/app/dashboard/settings/page.tsx`
- هدف: تنظیم اطلاعات برند، ساعت‌ها، منوهای زمان‌دار، رزرو، پرداخت و ظاهر عمومی.

## رابط و رفتار

بخش اطلاعات کسب‌وکار و slug/contact/address؛ ساعات هفتگی تهران؛ scheduled menus صبحانه/ناهار/شام با ساعت و دسته‌های فعال؛ رزرو/پیش‌پرداخت در صورت entitlement؛ رنگ/لوگو؛ مالیات و سرویس، درگاه پرداخت و کارت‌به‌کارت، لینک/QR preview؛ sticky save وقتی dirty.

## API و داده

GET/PATCH /api/business؛ GET /api/categories؛ settings JSON شامل operatingHours, scheduledMenus, reservations, cardTransfer, payments وغيرها.

## الزامات بازنویسی

dirty state با saved snapshot مقایسه؛ فقط قسمت‌های مجاز/فرم معتبر ذخیره؛ ساعت شبانه تا روز بعد درست تفسیر شود؛ payment validation فقط server callback معتبر؛ setting متعلق به tenant.

این صفحه باید با shell مشترک داشبورد و اصول UI/RTL در `README.md` این پوشه هماهنگ باشد. برای schema کامل، منبع و routeهای API ذکرشده را بخوان.

## مشخصات سطح پیاده‌سازی

### ساختار فرم و مدل

`GET /api/business` یک `{item}` می‌دهد و `PATCH` کل business فرم را ذخیره می‌کند. کلیدهای اصلی شامل نام/slug/نوع/توضیح/تلفن/آدرس/اینستاگرام، رنگ/لوگو، مختصات، درصد مالیات و خدمات و `acceptOrders` هستند. `settings` JSON بخش‌های فرعی را نگه می‌دارد: ساعت کاری، منوهای زمان‌بندی‌شده، رزرو، انتقال کارت‌به‌کارت و تنظیم‌های دیگر. هنگام خواندن، `settings` خالی باید به `{}` نرمال شود.

- اطلاعات عمومی: نام، نوع (کافه، رستوران، فست‌فود، نانوایی/شیرینی، فروشگاه)، توضیح کوتاه، تلفن، اینستاگرام و نشانی.
- ساعت کاری: هفت روز با شماره روز JS؛ فهرست UI از شنبه (`6`) تا جمعه (`5`) است. فعال‌سازی کلی و open هر روز جداست، هر روز start/end با ساعت 24ساعته دارد. Backend و منوی مشتری با `Asia/Tehran` تصمیم می‌گیرند؛ پایان کوچک‌تر از شروع می‌تواند بازه شبانه باشد.
- منوهای زمان‌دار: صبحانه/ناهار/شام هرکدام `id,name,enabled,start,end,days,categoryIds` دارند. دسته‌های انتخاب‌شده فقط در بازه همان منو ظاهر می‌شوند و دسته‌هایی که در زمان‌بندی نیستند همیشگی می‌مانند. فقط دسته‌های فعال قابل انتخاب‌اند.
- رزرو: بخش فقط با entitlement `reservations` قابل تغییر است. تنظیم `enabled`, `requireDeposit`, `depositPerGuest`, `durationMinutes` دارد؛ پیش‌پرداخت می‌تواند خاموش بماند و مدت پیش‌فرض ۹۰ دقیقه است.
- پرداخت کارت‌به‌کارت: `enabled`, شماره کارت، صاحب حساب، بانک و دستور پرداخت. فعال‌بودن به معنی تأیید خودکار پرداخت نیست؛ مشتری رسید/اطلاعات را می‌بیند و کارمند دریافت وجه را در سفارش تأیید می‌کند.
- ظاهر: رنگ از palette، نماد برند، لینک `/m/:slug`، QR و پیش‌نمایش.
- صدور صورتحساب: درصد مالیات/خدمات و پذیرش سفارش آنلاین؛ مختصات نقشه برای محاسبه فاصله و محدوده ارسال؛ تنظیم cashback در کارت جداگانه.

### تغییرات ذخیره‌نشده و خطا

صفحه snapshot `saved` را با `biz` از طریق JSON compare می‌کند؛ نوار ثابت ذخیره/بازگشت فقط وقتی dirty است دیده می‌شود. هنگام save دکمه loading، درخواست PATCH و سپس جایگزینی هر دو state با پاسخ canonical سرور لازم است. خطا toast می‌شود و داده و dirty بودن حفظ می‌شود. دسته‌ها جداگانه بارگیری می‌شوند؛ شکست فهرست دسته نباید فرم تنظیمات را نابود کند.

### معیار پذیرش

پیش از save مقادیر درصد، شماره کارت/slug و زمان‌ها را validate کن؛ دسترسی/feature و tenant isolation فقط در سرور enforce می‌شوند. ساعت شبانه و روزهای هفته را با helperهای موجود آزمایش کن. QR باید از origin واقعی + slug جاری ساخته شود، اما clipboard یا link external در محیط محدود به پیام خطای قابل فهم نیاز دارند. در صفحه موبایل ساعت‌ها wrap نشوند و بنر ذخیره ثابت روی دکمه‌های انتهایی صفحه را نپوشاند.
