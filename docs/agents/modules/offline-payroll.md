# آرشیو حقوق و فیش کارکنان در Windows آفلاین

وضعیت ۲۰۲۶-۱۰-۲۷: مشاهدهٔ فقط‌خواندنی ۱۲ دورهٔ اخیر، جزئیات فیش و چاپ محلی پیاده شده است. محاسبه/اصلاح کارکرد، ثبت مرخصی و تشویقی، قطعی‌کردن لیست، پرداخت حقوق، سند حسابداری، خروجی بیمه و مالیات هنوز آفلاین نیستند.

## کاربرد

وقتی اینترنت قطع می‌شود، مدیر مجاز باید بتواند لیست‌های حقوقی دریافت‌شده را در برنامهٔ Windows باز کند، فیش یک کارمند را ببیند و همان فیش را از چاپگر محلی چاپ یا PDF کند. این قابلیت فقط آرشیو خروجی محاسبهٔ سرور است و محاسبهٔ حقوق آفلاین را وانمود نمی‌کند.

## دسترسی و داده

- `GET /api/offline-dashboard/snapshots/payroll` فقط با Bearer terminal فعال و entitlementهای `cashier_pos` و `payroll` پاسخ می‌دهد. terminal همان کسب‌وکار را از سمت سرور تعیین می‌کند؛ شناسهٔ کسب‌وکار از query/body پذیرفته نمی‌شود.
- سرور حداکثر ۱۲ لیست حقوق اخیر را می‌گیرد. برای هر دوره، ردیف‌های فیش، جمع ناخالص/خالص/بیمه/مالیات و نوع/مبلغ تسویهٔ انجام‌شده ارسال می‌شود. سقف هر آرشیو ۳٬۰۰۰ فیش و سقف عمومی snapshot چهار مگابایت است؛ عبور از سقف خطای 413 می‌دهد و پاسخ ناقص ذخیره نمی‌شود.
- projection فیش فقط نام، نام پدر، کد ملی، شماره بیمه، عنوان/کد شغل، تاریخ شروع کار، نام صاحب حساب، شماره حساب و شبا را از `staffSnapshot` می‌فرستد؛ اجزای ناشناختهٔ پروفایل حذف می‌شوند. درآمد/کسری فقط label/key/مبلغ و flag چاپی/حسابداری مجاز دارند. هشدارها و آرایه‌های خط محدود می‌شوند.
- payload snapshot در جدول محلی عمومی workspace به شکل DPAPI در Windows رمز می‌شود. دادهٔ بازشده با فرمان Tauri `offline_workspace_payroll` فقط پس از بررسی PIN مدیر محلی برمی‌گردد. PIN از همان rate-limit تلاش ناموفق محلی استفاده می‌کند؛ این PIN جای احراز هویت آنلاین را نمی‌گیرد.
- سرور فقط آخرین revision این dataset را برای terminal نگه می‌دارد تا نسخه‌های پیشین اطلاعات حقوقی باقی نمانند. snapshot هفت روز اعتبار دارد؛ پس از انقضا فقط برای مشاهده/چاپ قابل استفاده است. پاسخ 401/403 پس از اتصال snapshot محلی را پاک می‌کند.

## همگام‌سازی و رابط Windows

- worker هر ده دقیقه و با درخواست «دریافت نسخهٔ تازه» endpoint را می‌خواند، tenant، schema، UUID، revision، سقف دوره و شکل آرایه‌ها را اعتبارسنجی می‌کند و تنها سپس snapshot را در SQLite محلی ذخیره می‌کند.
- تب «حقوق و فیش‌ها» تا ورود PIN هیچ نام یا مبلغی را از SQLite به رابط نمی‌آورد. پس از بازشدن، دوره‌ها و خلاصهٔ خالص قابل انتخاب‌اند؛ فهرست کارکنان دوره ساعت‌های کارکرد/اضافه‌کاری و خالص را نشان می‌دهد.
- «مشاهده / چاپ» فیش ذخیره‌شده را در WebView محلی و قالب A4 چاپ می‌کند؛ هیچ صفحهٔ وب، API یا سرویس چاپ ابری لازم نیست. با رفتن به تب دیگر، داده از state و DOM پاک می‌شود و برای دیدن دوباره PIN لازم است.
- این ماژول command مالی تولید نمی‌کند و endpoint POST ندارد. هیچ پرداخت، سند، محاسبهٔ حقوق، ارسال بانکی، فایل بیمه یا فایل مالیاتی در حالت آفلاین ساخته نمی‌شود.

## فایل‌های اصلی

- `src/lib/offline-dashboard.ts`: entitlement، query tenant-scoped، projection حداقلی و snapshot حقوق.
- `src/lib/offline-payroll-core.ts`: projection خالص و bounded اطلاعات چاپی کارمند و ردیف‌های دریافت/کسری.
- `windows-bridge/src-tauri/src/offline.rs`: دریافت دوره‌ای، پاک‌سازی در 401/403، وضعیت sync و فرمان PINدار خواندن snapshot.
- `windows-bridge/src-tauri/src/main.rs`: ثبت Tauri command.
- `windows-bridge/ui/index.html`, `windows-bridge/ui/pos.js`, `windows-bridge/ui/style.css`: تب، قفل PIN، انتخاب دوره، مشاهده/چاپ فیش A4 و قفل مجدد هنگام جابه‌جایی تب.
- `tests/offline-payroll-projection.test.cjs`: اثبات allowlist فیلد و پاک‌سازی داده‌های اضافی/نامعتبر.

## محدودیت‌های باز

برای تکمیل ماژول باید commandهای مرخصی و تعدیل حقوق، محاسبهٔ محلی که دقیقاً همان `payroll-core` سرور باشد، ادیت کارکرد با conflict، تأیید لیست و ایجاد سند، ثبت تسویهٔ حقوق/بیمه/مالیات با idempotency، و خروجی‌های رسمی بررسی شوند. تراکنش پرداخت یا سند را نباید در client به‌تنهایی اعمال کرد؛ برای سرور به handler اختصاصی با قفل دوره، کنترل snapshot و کلید یکتا نیاز است. تست DB/integration، migration و پرداخت واقعی در این گام اجرا نشده‌اند.
