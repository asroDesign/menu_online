# فهرست رستوران‌ها

> مشخصات بازسازی عامل برای صفحه/جریان عمومی یا سیستمی.

- مسیر: `/restaurants`
- منبع فعلی: `src/app/restaurants/page.tsx`
- هدف: دایرکتوری عمومی کسب‌وکارهای قابل مشاهده و پل ورود به منوی هر کدام.

## رابط و جریان

لیست کارت رستوران با نام، نوع، آدرس/تصویر و لینک مشاهده منو؛ در نسخه فعلی جست‌وجو/فیلتر و empty state مستقل وجود ندارد.

## API و داده

داده عمومی businesses و پیوند /m/:slug.

## قواعد بازسازی

فقط کسب‌وکارهای public و active؛ pagination/query اگر داده زیاد است؛ private phone/settings نشت نکند.

برای schema دقیق و شرط‌های موجود، فایل‌های source و API بالا را بخوان. UI عمومی باید tenant-isolated، RTL و responsive باشد.

## مشخصات سطح پیاده‌سازی

### منبع و نمایش

صفحه server-rendered و dynamic است؛ ابتدا `ensureDemoData()` اجرا می‌شود، سپس کسب‌وکارهای تعلیق‌نشده دریافت می‌شوند. رکورد داخلی `admin-panel` حذف می‌شود. برای هر کسب‌وکار featureها محاسبه می‌شوند: badge سفارش آنلاین وقتی `acceptOrders` و حداقل یکی از `self_order`/`delivery_order` فعال باشند؛ badge ارسال با `delivery_order`. CTA هر کارت به `/m/:slug` می‌رود.

کارت، رنگ و نماد برند، نام، توضیح کوتاه، قابلیت سفارش و ارسال را نشان می‌دهد. سربرگ لینک صفحه اصلی و ورود مدیران دارد. در کد فعلی جستجو، فیلتر، pagination و EmptyState مستقل وجود ندارد؛ به عنوان رفتار موجود فرض نکن.

### حریم خصوصی و رشد داده

فقط کسب‌وکارهای public/غیرمعلق فهرست شوند؛ شماره خصوصی، ایمیل مدیر، اطلاعات پرداخت یا تنظیمات داخلی نباید در props/client data بیاید. در صورت رشد تعداد tenantها، pagination/search را با API عمومی محدود و کنترل‌شده اضافه کن؛ داده همه tenantها را یکجا به کلاینت نفرست.
