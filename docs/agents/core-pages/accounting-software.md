# صفحهٔ حسابداری رستوران و کافه

## مسیر، هدف و اجرا

- صفحهٔ عمومی: `/accounting-software`
- فایل‌ها: `src/app/accounting-software/page.tsx`, `accounting-software.module.css`, `accounting-story.module.css`, `src/components/marketing/accounting-story.tsx`
- دادهٔ برند و canonical از تنظیمات جاری سایت می‌آیند؛ schema از `SoftwareApplication` استفاده می‌کند.
- صفحهٔ عمومی به دادهٔ واقعی مشتری/حسابداری یا API دفتر وصل نیست. تمام ارقام و کارکردهای انیمیشنی سناریوهای توضیحی‌اند.

## سکشن‌ها و تعامل

1. Hero با نمونهٔ سند دوبل، CTA پلن/ثبت‌نام و اتصال نمادین صندوق/انبار/بانک.
2. `ProfitStory`: نمودار تعاملی دو بازه و slider هزینهٔ افزوده؛ تغییر آن سود نمایشی را زنده تغییر می‌دهد. عنوان با مسئلهٔ «این ماه واقعاً چقدر سود کردیم؟» شروع می‌شود.
3. `BusinessStory`: انتخاب صنف (رستوران، کافه، فست‌فود، فروشگاه/خدمات) و نمایش مسئله و قابلیت مرتبط.
4. `SaleStory`: چهار مرحلهٔ فروش، مصرف نمونه، سند دوبل و نتیجهٔ پس از بهای مواد؛ play/pause/replay و انتخاب مرحله دارد؛ دادهٔ واقعی نمی‌خواند.
5. تب‌های اتصال به routeهای واقعی پنل، سپس `OfflineStory`: شبیه‌سازی محلی اینترنت/صف؛ نمونهٔ افزوده‌شده با localStorage در مرورگر حفظ می‌شود، قطع اینترنت واقعی نیست و جریان‌های پشتیبانی‌شدهٔ صندوق ویندوز را بازسازی کامل نمی‌کند.
6. Feature Explorer، معرفی صنف و نقش‌های مدیر/حسابدار، کارت‌های امنیت و مقایسهٔ دسترس‌پذیر و افقی.
7. FAQ محدودیت‌ها را شفاف می‌گوید؛ از جمله عدم اتصال مستقیم به API بانک و محدودیت آفلاین.

## نسبت با نمونه

چیدمان مسئله‌محور، «حسابداری مخصوص صنف شما»، حفاظت اطلاعات و سؤال سود واقعی از صفحهٔ مرجع بیامنو الهام گرفته؛ کد/تصویر آن منتقل نشده و انیمیشن‌ها با CSS/React و هویت MenuPeak ساخته شده‌اند.

## مسیرهای عملیاتی که صفحه به آنها پیوند می‌دهد

`/dashboard/profit-loss`, `/dashboard/accounting`, `/dashboard/reports`, `/dashboard/bank`, `/dashboard/cheques`, `/dashboard/receivables`, `/dashboard/inventory`, `/dashboard/pricing`, `/dashboard/income-expense`, `/dashboard/payroll`, `/dashboard/assets`.

## محدودیت و صحت محتوا

- دسترسی و رفتار صفحه‌های پیوندشده تابع role، plan و entitlement واقعی است.
- پیش‌نمایش سند/نمودار در صفحه، داده یا گزارش زنده نیست.
- عملیات آفلاین کامل حسابداری ادعا نمی‌شود؛ برخی عملیات POS در Windows ذخیره محلی دارند.
- دفتر مدیر سامانه که برای فاکتورهای اشتراک، هزینه‌های MenuPeak، چک سامانه و reconciliation اضافه شده، با حسابداری tenant رستوران یکی نیست؛ مشخصاتش در [ماژول حسابداری سامانه](../modules/platform-accounting.md) است.

## صحت‌سنجی

`npx tsc --noEmit` و ESLint روی صفحه و کامپوننت‌های تغییرکرده سبز شدند. پیش‌نمایش Chrome در این اجرا ممکن نشد: bind محلی dev server با `EPERM` در sandbox رد شد. آزمون‌های DB/API و اعمال migration اجرا نشده‌اند.
