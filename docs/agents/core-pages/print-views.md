# رسیدها و اسناد چاپی

> مشخصات بازسازی عامل برای صفحه/جریان عمومی یا سیستمی.

- مسیر: `/print/invoice/:id, /print/receipt/:id, /print/doc/:id`
- منبع فعلی: `src/app/print/invoice/[id]/page.tsx, receipt/[id]/page.tsx, doc/[id]/page.tsx`
- هدف: چاپ رسید سفارش مشتری، فاکتور اشتراک SaaS و سند حسابداری.

## رابط و جریان

صفحه چاپ مینیمال، بدون navigation، اطلاعات کسب‌وکار/سفارش/اقلام/مبالغ/پرداخت؛ receipt سفارش روی رول ۸۰ میلی‌متری؛ invoice اشتراک SaaS روی A4؛ doc خطوط بدهکار/بستانکار سند حسابداری. دکمه print و @media print.

## API و داده

سرور fetch داده مربوطه از DB/API؛ لینک‌های استفاده‌شده از orders/suppliers/accounting/stock.

## قواعد بازسازی

دسترسی به سند tenant-scoped؛ صفحه با کاغذ و چاپگر 58/80mm یا A4 سازگار بر اساس نوع؛ فونت فارسی embed/load؛ جمع مبلغ server-sourced.

برای schema دقیق و شرط‌های موجود، فایل‌های source و API بالا را بخوان. UI عمومی باید tenant-isolated، RTL و responsive باشد.

## مشخصات سطح پیاده‌سازی

### سه نوع سند متفاوت

- `/print/receipt/:id` رسید سفارش POS مشتری با عرض چاپ ۸۰ میلی‌متر است. دسترسی نیاز به login، entitlement `cashier_pos` و سفارش همان tenant دارد. اقلام و تعداد، مشخصات سفارش، subtotal، تخفیف، هزینه ارسال، مالیات، سرویس، cashback، کل، وضعیت پرداخت/یادداشت و اطلاعات تماس کسب‌وکار را با تاریخ شمسی چاپ می‌کند.
- `/print/invoice/:id` فاکتور اشتراک SaaS است، نه فاکتور مشتری رستوران. مالک کسب‌وکار مربوط یا مدیر پلتفرم با مجوز `accounting` دسترسی دارد. صفحه اطلاعات buyer/owner، شماره و وضعیت invoice، طرح، دوره صورت‌حساب، تعداد ماه، تخفیف، مبلغ به حروف و دستور واریز اگر پرداخت‌نشده باشد را روی A4 می‌آورد.
- `/print/doc/:id` سند حسابداری tenant است. login و entitlement accounting لازم است؛ سند، سال مالی، حساب‌ها و خطوط را join می‌کند و نوع/source، وضعیت draft، سند برگشتی، بدهکار/بستانکار، جمع‌ها و جای امضا را چاپ می‌کند.

### پیاده‌سازی چاپ

هر route داده را در سرور از DB و با guard tenant/role دریافت می‌کند؛ id تصادفی مجوز را جایگزین نمی‌کند. کنترل PrintButton فقط UX است؛ stylesheet `@media print` باید nav و دکمه را حذف، رنگ پس‌زمینه را پاک و اندازه کاغذ هر نوع را تنظیم کند. فونت فارسی، صفحه‌بندی جدول اقلام، کسرها و `dir` ارقام/شماره پیگیری را روی Chrome چاپی و PDF بررسی کن. ارقام مالی از رکورد سرور و محاسبات رسمی می‌آیند، نه query یا فرم.

## فیش عامل محلی

صف چاپ خودکار جدا از صفحهٔ چاپ مرورگر است و متن آن توسط `formatReceiptText` در `src/lib/receipt-layout.ts` و wrapper `receiptText` در `src/lib/orders.ts` ساخته می‌شود. `businesses.settings.printerSettings.receiptHeader/receiptFooter` در قاب چاپ قرار می‌گیرند. فیش مشتری و کافه مبلغ/جمع دارند؛ بلیت آشپزخانه مبلغ کل ندارد و اقلام را با categoryهای دستگاه فیلتر می‌کند. خروجی عامل محلی برای رول حرارتی ۳۲ نویسه در هر خط است؛ جدول متنی شماره/شرح قلم/تعداد/مبلغ دارد و متن بلند wrap می‌شود. نسخه‌ها و رویدادهای ایجاد، تسویه و آماده‌شدن در [راهنمای چاپگرها](../modules/printers.md) مستند شده‌اند. تنظیمات/Jobها از `GET/PATCH /api/business` و `/api/r/printjobs` می‌آیند؛ retry صف ممکن است چاپ کاغذی را تکرار کند.

صفحهٔ چاپ مرورگر `/print/receipt/:id` نیز سربرگ، مشخصات سفارش، خلاصهٔ مالی و پابرگ قاب‌دار و جدول HTML سه‌ستونهٔ شرح کالا/تعداد/مبلغ دارد. این نسخه را جدا از متن عامل روی Chrome و PDF و عرض واقعی ۸۰ میلی‌متر کنترل کن.

برای چاپ دستی از modal سفارش و سفارش‌گیر صندوق، دکمه‌ها از `POST /api/orders/:id/print` استفاده می‌کنند و به مسیر مستقل مرورگر `/print/receipt/:id` navigation نمی‌کنند. این مسیر چاپگر مشتری/آشپزخانه را از تنظیمات دستگاه انتخاب می‌کند؛ صفحهٔ `/print/receipt/:id` فقط وقتی با URL مستقیم باز شود، همان صفحهٔ مستقل read-only و مناسب چاپ مرورگر است.
