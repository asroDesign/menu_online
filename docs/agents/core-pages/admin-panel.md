# پوسته پنل مدیر سامانه

> مشخصات بازسازی عامل برای `/admin`.

## نقش و مسیر

- صفحه: `src/app/admin/page.tsx`; پوسته تعاملی: `src/components/admin/shell.tsx`.
- route احراز هویت مدیر را بررسی می‌کند؛ مجوز هر بخش از permissionهای `ADMIN_DEPTS` فیلتر می‌شود. endpointهای پنل نیز authorization را مجدداً enforce می‌کنند.
- نوار کناری راست/RTL گروه‌بندی‌شده و دارای اسکرول است؛ در موبایل به drawer دسترس‌پذیر با Escape، focus trap و بازگرداندن focus تبدیل می‌شود.

## هویت بصری و رنگ سامانه

- پوسته از palette آبی پیش‌فرض و زمینه روشن استفاده می‌کند؛ نوار کناری سرمه‌ای با رنگ انتخابی سامانه برای نشان برند و گزینه فعال است.
- `usePlatformBranding()` رنگ platform را از API عمومی branding می‌خواند؛ `brandThemeStyle()` آن را به wrapper shell می‌بندد، بنابراین تغییر رنگ در تنظیمات به کارت‌ها و primary controls پنل می‌رسد.
- مدیر مجاز رنگ را در بخش `تنظیمات سامانه > هویت بصری سامانه` تغییر می‌دهد. این رنگ جدا از `businesses.accentColor` است.

## رفتار و تغییر وضعیت

- `ADMIN_GROUPS` و `TABS` منبع ناوبری و permission هستند. انتخاب tab در hash صفحه نگه‌داری می‌شود و `go()` به ابتدای محتوا می‌رود.
- محتوای اصلی یک tab در هر زمان رندر می‌شود؛ زیرصفحه‌های حسابداری/تیکت پارامترهای جست‌وجو را از props می‌گیرند.
- رویداد `platform-branding-updated` با ذخیره تنظیمات باعث بارگیری دوباره branding می‌شود؛ نام/لوگو و رنگ هم‌زمان تازه می‌شوند.

## محدودیت‌های بازسازی

- رنگ پوسته را از CSS ثابت در admin shell تعیین نکن؛ از `brandThemeStyle` و `PlatformBrandingRuntime` استفاده کن.
- نوار کناری و drawer را از نظر focus، اسکرول مستقل و دسترسی permission حفظ کن.
- این صفحه اطلاعات مالی/کاربری را از tab componentهای موجود می‌گیرد؛ بازطراحی ناوبری نباید دسترسی یا API آنها را تغییر دهد.
