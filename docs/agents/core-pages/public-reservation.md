# رزرو میز سمت مشتری

> مشخصات بازسازی عامل برای صفحه/جریان عمومی یا سیستمی.

- مسیر: `/m/:slug/reserve`
- منبع فعلی: `src/app/m/[slug]/reserve/page.tsx + src/components/reservation-form.tsx`
- هدف: فرم رزرو عمومی مشتری با انتخاب زمان شمسی و پیش‌پرداخت اختیاری.

## رابط و جریان

اطلاعات مشتری/شماره/تعداد نفر، انتخاب Jalali date/time و مدت، توضیح؛ نمایش نیاز به deposit و راهنمای پرداخت؛ تأیید و success summary/status. مسیر فقط در feature reservations و تنظیم enabled نمایش داده شود.

## API و داده

POST /api/public/:slug/reservations؛ jalali-input/date picker مشترک؛ settings/business برای public route.

## قواعد بازسازی

timezone Asia/Tehran؛ تداخل میز/ظرفیت، حداقل زمان و مبلغ deposit server-side؛ confirmation SMS بر اساس وضعیت backend؛ تاریخ ورودی normalize شود.

برای schema دقیق و شرط‌های موجود، فایل‌های source و API بالا را بخوان. UI عمومی باید tenant-isolated، RTL و responsive باشد.

## مشخصات سطح پیاده‌سازی

### فرم و مقادیر

فرم فقط در صورت entitlement و `settings.reservations.enabled` فعال است. فیلدها: نام (اجباری، ۲ تا ۸۰ نویسه)، موبایل (اجباری)، تعداد مهمان (۱ تا ۳۰، پیش‌فرض ۲)، تاریخ/ساعت شمسی با `PersianDateInput`، توضیح اختیاری تا ۳۰۰ نویسه. مدت رزرو در تنظیمات رستوران است. وقتی پیش‌پرداخت لازم باشد مبلغ قابل نمایش برابر تعداد مهمان × مبلغ هر نفر است؛ مقدار نمایش‌داده‌شده اطلاع‌رسانی است و سرور آن را دوباره محاسبه می‌کند.

### ارسال و حالت نهایی

Submit، `startsAt` را به ISO تبدیل و `{name,phone,guestCount,startsAt,note}` را به `POST /api/public/:slug/reservations` می‌فرستد. پاسخ حاوی شناسه و مبلغ پیش‌پرداخت است؛ صفحه کد پیگیری نشان می‌دهد و صریح می‌گوید درخواست ثبت‌شده رزرو تأییدشده نیست. در صورت مبلغ deposit، قطعی شدن پس از هماهنگی/ثبت وجه است؛ بدون deposit نیز تأیید ظرفیت با رستوران است. خطای API کنار فرم می‌ماند، submit busy/disabled است و با موفقیت فرم جایگزین خلاصه می‌شود.

### قواعد و معیار پذیرش

تاریخ شمسی تنها presentation است؛ زمان با timezone تهران به instant معتبر تبدیل شود. جلوگیری از رزرو گذشته، ساعت بسته، ظرفیت/تداخل و محاسبه سپرده باید سمت سرور باشد. ارسال SMS تایید/رد با جریان مدیریت رزرو و وضعیت backend انجام می‌شود، نه با ارسال فرم عمومی. مسیر غیرمجاز/غیرفعال را صفحه مشتری لینک ندهد. ورودی موبایل LTR، تاریخ‌گزین در دسترس صفحه‌کلید و دکمه ارسال در نمایش موبایل تمام عرض باشد.
