# کیوسک مشتری

> مشخصات بازسازی عامل برای صفحه/جریان عمومی یا سیستمی.

- مسیر: `/kiosk/:slug`
- منبع فعلی: `src/app/kiosk/[slug]/page.tsx + src/components/kiosk-client.tsx`
- هدف: رابط self-service روی صفحه لمسی؛ می‌تواند سفارش را ثبت و به POS متصل شود.

## رابط و جریان

نمایش برند و کاتالوگ بزرگ لمسی، انتخاب غذا و cart، انتخاب روش تحویل/میز طبق config، ثبت، شماره سفارش و وضعیت اتصال POS؛ polling job status؛ مراحل پرداخت/تأیید کارتخوان، error/retry و reset برای مشتری بعدی.

## API و داده

server public menu builder؛ GET /api/public/:slug/pos؛ GET/POST /api/public/:slug/pos/:id با token؛ POST /api/public/:slug/orders.

## قواعد بازسازی

فقط کسب‌وکار فعال و kiosk entitlement؛ server-side price validation؛ زمان idle reset برای پاک‌سازی PII/cart؛ POS token محرمانه؛ touch targets بزرگ و fullscreen قابل استفاده.

برای schema دقیق و شرط‌های موجود، فایل‌های source و API بالا را بخوان. UI عمومی باید tenant-isolated، RTL و responsive باشد.

## مشخصات سطح پیاده‌سازی

### راه‌اندازی و پیکربندی

صفحه سرور `/kiosk/[slug]` کسب‌وکار موجود، غیرمعلق و entitlement کیوسک را بررسی می‌کند، تنظیمات `kiosk` را با پیش‌فرض‌ها merge می‌کند و قالب معتبر query/config را به `KioskClient` می‌دهد. روش سفارش/پرداخت فقط وقتی قابل نمایش است که تنظیم کیوسک و featureهای IPG یا tablet POS هر دو اجازه دهند؛ POS آنلاین نیز به وضعیت/پیکربندی خودش وابسته است. قالب نامعتبر باید به قالب پیش‌فرض برگردد.

### جریان لمسی

محصولات و دسته‌ها از منوی عمومی می‌آیند. کاربر اقلام و تعداد را انتخاب می‌کند، سبد را مرور می‌کند، نوع تحویل/میز و داده‌های لازم (مثلاً شماره مشتری) را وارد می‌کند، سپس سفارش ثبت می‌شود. پاسخ می‌تواند سفارش را برای کارت‌خوان به صف ببرد؛ در این حالت صفحه وضعیت POS را از endpointهای public POS با token کوتاه‌عمر poll می‌کند تا تایید، شکست یا انقضا را نمایش دهد. موفقیت مالی فقط با تأیید backend/POS معتبر اعلام شود.

صفحه باید وضعیت idle، خالی بودن منو، سبد، submitting، پرداخت در انتظار کارتخوان، موفق، خطا و بازگشت به شروع را داشته باشد. بعد از سفارش یا timeout کیوسک، شماره تلفن، یادداشت، cart و state مشتری قبلی پاک شود.

### معیار پذیرش

همه دکمه‌ها touch target بزرگ داشته باشند؛ در نمایش landscape/portrait scroll و focus منطقی کار کند؛ session عمومی دسترسی tenant دیگری ندهد. قیمت و موجودی فقط از route سفارش تعیین شود؛ secret/token در URL یا log عمومی ذخیره نشود. timeout شبکه و خروج کابل POS مسیر retry/لغو روشن داشته باشد.
