# ماندگاری نمایش چیدمان دلخواه چاپگر

## مسئله

در «تنظیمات ← پرینترها ← چاپ خودکار»، مدیر می‌توانست در «موقع ثبت سفارش با میز» یک یا چند چاپگر مشخص انتخاب کند و تنظیم را ذخیره کند. چون تعداد نسخه‌های پیش‌فرض این رویداد با preset «مشتری و آشپزخانه» برابر است، صفحه پس از ذخیره فقط همان preset را انتخاب‌شده نشان می‌داد. شناسه‌های چاپگر در تنظیمات کسب‌وکار باقی می‌ماندند، ولی مدیر برای دیدن مسیر اختصاصی دوباره باید «چیدمان دلخواه» را باز می‌کرد.

## تغییر اجرایی

- `src/lib/printer-policy.ts` اکنون با `printerRulePresetKey` طبقه‌بندی انتخاب‌ها را بر پایهٔ تعداد نسخه‌ها و مسیرهای اختصاصی چاپگر انجام می‌دهد. هر انتخاب اختصاصی برای مشتری، آشپزخانه یا کافه باعث می‌شود قانون در UI «چیدمان دلخواه» باقی بماند.
- `applyPrintCopyPreset` انتخاب preset نام‌دار را یکپارچه می‌کند: تعداد نسخه‌ها را تغییر می‌دهد و مسیرهای اختصاصی را پاک می‌کند تا preset، مسیردهی خودکار را به‌درستی اعمال کند.
- `src/modules/printer-settings.tsx` از این توابع استفاده می‌کند و متن راهنما توضیح می‌دهد که انتخاب دستگاه پس از ذخیره در حالت سفارشی می‌ماند.
- API، ساختار ذخیره‌سازی، داده‌های موجود و migration تغییر نکردند. انتخاب‌های قبلی چاپگر همچنان از همان `printerSettings` خوانده می‌شوند. `next-env.d.ts` نیز برای import فایل route types تولیدشدهٔ Next 16 پس از اجرای `next typegen` به‌روز شد.

## آزمون و محدوده

`tests/printer-settings.test.cjs` طبقه‌بندی قانون با مسیر اختصاصی آشپزخانه/مشتری، برابری تعداد نسخه با preset، تعداد متفاوت و بازگشت از مسیر سفارشی به preset را بررسی می‌کند. پنج تست ماژول و کل مجموعهٔ تست (۱۴۸ موفق، صفر شکست، ۷ تست PostgreSQL-dependent اجرا نشده)، ESLint هدفمند، `npx next typegen` با Node 20، `npm run typecheck -- --incremental false` و `git diff --check` موفق شدند. اجرای typecheck با Node 18 به route types قدیمی `.next` برخورد کرد؛ اجرای ابزارهای Next با Node 20.18.1 و import جدید `next-env.d.ts` مشکل را برطرف کرد. تست چاپ فیزیکی با Agent یا دستگاه واقعی جزو این اصلاح نبود.
