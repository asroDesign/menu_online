# تعریف کالای تازه در انبار آفلاین

## مسئله

اپ Windows می‌توانست فاکتور ورود و گردش انبار را برای کالاهای از قبل همگام‌شده در صف بگذارد، اما هنگام قطع اینترنت امکان تعریف قلم جدید نداشت. مدیر مجبور بود تا اتصال دوباره صبر کند و بعد فاکتور یا موجودی افتتاحیه را وارد کند.

## آنچه انجام شد

- snapshot انبار اکنون دسته‌بندی‌های همان کسب‌وکار را نیز می‌فرستد تا فرم محلی بتواند دسته و انبار را از دادهٔ cacheشده انتخاب کند.
- تب انبار فرم «افزودن کالای جدید» دارد: نام و SKU اختیاری، واحد انبار و دستور تهیه، تبدیل استاندارد جرم/حجم یا ضریب دستی، انبار، دسته، موجودی آغازین، بهای افتتاحیه، آخرین بهای خرید، حداقل موجودی، نقطه سفارش، تاریخ انقضای شمسی، ردیابی موجودی، فعال‌بودن و شرح افتتاحیه.
- ثبت نیازمند snapshot معتبر و PIN مدیر محلی است. فرمان `inventory/create_item` با UUID و snapshot پایه در صف رمز‌شدهٔ DPAPI قرار می‌گیرد. خطای PIN، تاریخ، واحد، ضریب، مقدار، هزینه یا انتخابی خارج از snapshot در سمت دستگاه رد می‌شود.
- کالای تازه بلافاصله در لیست کالا یا انتخابگر فاکتور ظاهر نمی‌شود؛ تا رسیدن تأیید سرور شناسهٔ محلی غیرقابل استفاده است. UI این وضعیت را صریح نشان می‌دهد.
- سرور terminal، tenant فعال، entitlement، snapshot و تاریخ را دوباره بررسی می‌کند؛ تعلق انبار و دسته را کنترل می‌کند، نام را در انبار و SKU را در کسب‌وکار یکتا می‌سازد و اگر SKU خالی باشد کد تولید می‌کند.
- ساخت کالا، گردش موجودی آغازین و در صورت وجود ارزش افتتاحیه سند بدهکار موجودی/بستانکار سرمایه به‌همراه ledger فرمان در یک PostgreSQL transaction نوشته می‌شوند. `opening-item:<itemId>` مرجع سند است و فرمان UUID تکراری را idempotent می‌کند. موجودی افتتاحیه مثبت نیازمند entitlement `stock_movements` است.
- migration `0069_offline_inventory_item_creation.sql` فقط allowlist کنش جدول دفتر فرمان را برای `inventory/create_item` گسترش می‌دهد؛ down migration اگر سابقهٔ این فرمان وجود داشته باشد متوقف می‌شود.
- تاریخچهٔ سفارش محلی و سفارش‌های cacheشدهٔ سایت همچنان از تب صندوق بدون اینترنت قابل مشاهده‌اند. آخرین ۱۰۰ سفارش فوراً cache می‌شوند؛ دیدن کل سابقه به تکمیل backfill صفحه‌بندی‌شده پیش از قطعی نیاز دارد.

## محدودیت‌های فعلی

- تا همگام‌سازی موفق و دریافت snapshot تازه، کالای تازه قابل انتخاب در فاکتورهای جدید، recipe یا تولید نیست.
- ساخت فروشنده، ویرایش/حذف کالا، lotهای متعدد انقضا و تعریف recipe آفلاین نشده‌اند.
- مهاجرت دیتابیس اجرا نشده و این تغییر هنوز deployment نشده است. خطاهای duplicate و محدودیت‌های snapshot می‌توانند فرمان را conflict/rejected کنند و مدیر باید دستگاه را تازه‌سازی کند.

فایل‌های اصلی: `src/lib/offline-dashboard.ts`, `src/lib/offline-inventory.ts`, `src/app/api/offline-dashboard/inventory/route.ts`, `windows-bridge/offline-core/src/lib.rs`, `windows-bridge/src-tauri/src/offline.rs`, `windows-bridge/src-tauri/src/main.rs`, `windows-bridge/ui/index.html`, `windows-bridge/ui/pos.js` و migrationهای `0069`.

اعتبارسنجی انجام‌شده: TypeScript بدون emit، ESLint هدفمند، بررسی syntax فایل JavaScript رابط و `git diff --check`. دیتابیس، migration و آزمون integration اجرا نشدند. چون `cargo` و `rustc` در محیط موجود نیستند، کامپایل Rust/Tauri تأیید نشده است.
