# گزارش سود و زیان در Windows آفلاین — ۲۰۲۶-۱۰-۲۷

## رفتار اضافه‌شده

تب گزارش‌های Windows اکنون snapshot سود و زیان ۹۰ روز اخیر را در کنار گزارش فروش نشان می‌دهد. مدیر هنگام قطع اینترنت می‌تواند جمع فروش خالص، تخفیف، مالیات، بهای تمام‌شدهٔ ثبت‌شده، هزینه‌های عملیاتی، درآمد دیگر، سود خالص، روند روزانه و ۱۰۰ دستهٔ هزینهٔ برتر را بخواند. نمایش فقط‌خواندنی است و snapshot مثل بقیهٔ داده‌های پنل در SQLite محلی رمز‌شده نگه‌داری می‌شود.

## مجوز و محاسبه

- snapshot به مجوز `cashier_pos` و دست‌کم یکی از `sales_reports` یا `profit_loss` نیاز دارد. دادهٔ خلاصهٔ فروش فقط با مجوز گزارش فروش و P&L فقط با مجوز سود و زیان پر می‌شود؛ هر بخش مستقل پنهان می‌شود.
- درآمد P&L از سفارش‌های `paid` در بازه گرفته می‌شود: subtotal منهای تخفیف به‌علاوهٔ هزینهٔ تحویل. مالیات جدا گزارش می‌شود. هزینه/درآمد دیگر از تراکنش‌های غیر از منبع `sale` محاسبه می‌شود.
- COGS از مقدار تاریخی `orders.cogs` استفاده می‌کند و نسبت سفارش‌های دارای بهای مثبت در `cogsCoverage` می‌آید. این مقدار ممکن است در برخی سفارش‌های قدیمی ثبت نشده یا برآوردی باشد و با P&L آنلاین که recipe فعلی را برای سفارش‌ها محاسبه می‌کند هم‌ارز نیست؛ رابط این محدودیت را آشکار می‌کند.
- محدودیت payload: حداکثر ۵۰٬۰۰۰ سفارش P&L، ۲۰٬۰۰۰ تراکنش غیر sale، ۱۰۰ دستهٔ هزینهٔ اصلی به‌علاوهٔ تجمیع باقی دسته‌ها؛ سقف عمومی snapshot چهار مگابایت است. تجاوز از سقف به‌جای گزارش ناقص، با خطا رد می‌شود.
- هیچ فرمان تغییر حساب/سند یا ثبت مالی محلی در این تغییر اضافه نشده؛ گزارش و دادهٔ سرور read-only باقی می‌مانند. فروش آفلاین تا sync موفق وارد P&L رسمی نمی‌شود.

## فایل‌های اصلی

- `src/lib/offline-dashboard.ts`: entitlement مجزا، aggregate سروری و حدود دادهٔ P&L.
- `windows-bridge/ui/index.html`, `windows-bridge/ui/pos.js`, `windows-bridge/ui/style.css`: کارت‌های P&L، روند روزانه و جدول دستهٔ هزینه.
- `docs/agents/modules/offline-full-dashboard.md`, `docs/agents/module-capabilities.md`, `docs/agents/core-pages/api-contract-map.md`, `IMPLEMENTATION_STATUS.md`: ماتریس قابلیت، API و وضعیت.

## اعتبارسنجی و محدودیت‌ها

`npx tsc --noEmit --incremental false`، ESLint هدفمند، `node --check windows-bridge/ui/pos.js` و `git diff --check` موفق شدند. npm هشدار ناسازگاری نسخهٔ خودش با Node 18.17.1 را داد، اما فرمان‌ها موفق بودند. اتصال دیتابیس یا اجرای migration انجام نشد؛ schema جدیدی لازم نیست. `cargo` و `rustc` در محیط نیست، ولی Rust در این vertical slice تغییر نکرده است. این مرحله P&L را به‌صورت snapshot فقط‌خواندنی پوشش می‌دهد؛ دفتر کامل حساب‌ها، بازهٔ سفارشی، export/print و ثبت/اصلاح مالی هنگام قطعی هنوز آنلاین‌اند.
