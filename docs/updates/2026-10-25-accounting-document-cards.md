# بازطراحی اسناد حسابداری و اصلاح ثبت سند — ۲۰۲۶-۱۰-۲۵

## مرجع و دامنه
مرجع: https://honeykando.ir/admin/accounting و کد محلی organo-marketplace-shop در مسیر src/app/admin/accounting/page.tsx.
صفحه نمونه و صفحه محلی فقط در Chrome خوانده شدند؛ هیچ سند واقعی برای آزمون ثبت، حذف یا برگشت نشد. مخزن مرجع تغییر نکرد.

## رابط کاربری
- فهرست خلاصه به کارت مستقل هر سند تبدیل شد: شماره، شرح، تاریخ، وضعیت، منبع ثبت، چاپ، و عملیات مجاز.
- جدول حساب معین، تفصیلی، بدهکار، بستانکار و جمع‌ها مستقیم داخل کارت دیده می‌شود؛ شرح ردیف نیز قابل مشاهده است.
- مدل فعلی MenuPeak تفصیلی متصل به معین دارد؛ سه تفصیلی مستقل نمونه به‌صورت صوری ساخته نشده‌اند.
- فیلترهای سال/بازه/نوع/منبع/وضعیت/جستجو حفظ شدند. صفحه‌بندی ۲۰ سندی، وضعیت بارگذاری، خطا و تلاش مجدد افزوده شد.
- منابع حقوق، مطالبات، برگشت مطالبات و چک در نمایش/چاپ نام خوانا دارند.
- برگشت و قطعی‌سازی تأیید می‌گیرند. پیام برگشت توضیح می‌دهد که برگشت سند به‌تنهایی پرداخت یا سفارش مبنا را لغو نمی‌کند.
- جدول در عرض کم اسکرول داخلی دارد؛ عرض سند اصلی در بررسی Chrome در دسکتاپ ۱۴۴۰ و موبایل ۳۹۰ با عرض viewport برابر بود.

## قرارداد API
GET /api/acc/documents علاوه بر items و year، page و limit و total برمی‌گرداند. هر item دارای lines و برچسب‌های حساب است.
پیش‌فرض limit=20، سقف 100؛ page حداقل 1 است. مرتب‌سازی شماره نزولی است. خطوط همه اسناد صفحه با یک query محدود به businessId خوانده می‌شوند.
مصرف‌کننده فعلی در مخزن به قرارداد جدید منتقل شد؛ مصرف‌کننده خارجی احتمالی باید صفحه‌بندی را رعایت کند.
شناسه نامعتبر، سال ناموجود، ساختار خطوط نامعتبر و بیش از ۵۰۰ ردیف با خطای کنترل‌شده رد می‌شوند.

## یکپارچگی مالی
- بررسی sourceRef پس از قفل تراکنشی کسب‌وکار انجام می‌شود؛ ثبت مجدد منبع، سند قبلی را بازمی‌گرداند.
- ساخت سند برگشتی و علامت‌گذاری سند اصلی یک transaction هستند؛ قفل کسب‌وکار و سطر اصلی از برگشت هم‌زمان جلوگیری می‌کنند. sourceRef برگشت document-reversal:<id> است.
- ویرایش/حذف پیش‌نویس همان قفل را دارند. سال بسته و سند قطعی قابل حذف/ویرایش نیستند؛ ذخیره پیش‌نویس خالی خطای insert آرایه خالی ندارد.
- مبلغ منفی، NaN، Infinity و جمع خارج از محدوده امن رد می‌شوند. هزینه کسری داخلی مثل قبل به تومان گرد می‌شود.
- حساب غیرفعال برای ثبت جدید رد می‌شود؛ برگشت تاریخی و انتقال مانده پایان سال برای حساب غیرفعال مجاز باقی مانده‌اند.
- ایجاد سال هدف هنگام ویرایش پیش‌نویس داخل transaction انجام می‌شود.
هیچ migration یا تغییر ساختار دیتابیس لازم نیست.

- src/lib/accounting-document-core.ts: نام‌گذاری سلسله‌مراتب حساب، مبلغ و صفحه‌بندی.
- src/lib/accounting.ts: ثبت، برگشت، ویرایش و حذف اتمیک.
- src/app/print/doc/[id]/page.tsx: نام منابع.
- tests/accounting-documents.test.cjs: هفت آزمون جدید.

## اعتبارسنجی
- npm run typecheck: موفق.
- ESLint شش فایل کد/تست تغییرکرده: موفق.
- node --test tests/accounting-documents.test.cjs tests/payroll-core.test.cjs tests/pos-routing-settings.test.cjs tests/cashier-checkout.test.cjs: ۳۴ آزمون موفق.
- آزمون‌های جدید: حساب مفقود/چرخه والد؛ مبلغ نامعتبر؛ ثبت sourceRef هم‌زمان؛ برگشت هم‌زمان؛ rollback خطای میانی؛ حساب غیرفعال و جداسازی کسب‌وکار؛ پیش‌نویس خالی و محدودیت سال بسته.
- آزمون transaction با adapter حافظه‌ای و rollback شبیه‌سازی‌شده روی کد واقعی است؛ اثبات هم‌زمانی PostgreSQL واقعی نیست.
- Chrome: هفت کارت و جدول محلی، صفحه‌های ۱ و ۲ با limit=2، فیلتر حقوق، جستجوی شماره فارسی و گزارش تراز پاسخ موفق دادند. مجموع خطوط اسناد خوانده‌شده تراز بود.

## مرزها و ریسک باقی‌مانده
- آزمون نوشتن روی PostgreSQL آزمایشی اجرا نشد؛ داده مالی زنده تغییر داده نشد.
- بستن سال مالی هنوز مانده‌ها را پیش از ورود به transaction می‌خواند و برای رقابت هم‌زمان با ثبت سند نیازمند بررسی مستقل است.
- این تغییر، ممیزی کامل همه تولیدکنندگان سند، مهاجرت به تفصیلی‌های مستقل یا تضمین صحت سوابق مالی قدیمی نیست.
- برگشت کد به نسخه قبل migration ندارد؛ اسناد واقعی برگشتی نباید برای rollback نرم‌افزار حذف شوند.
