# بازبینی خطاها و تلاش برای دموی محلی — ۲۰۲۶-۱۰-۲۷

## تغییرات

- سه تست قراردادی با کد فعلی هم‌تراز شدند: ترتیب propهای کنترل OTP، محافظت مسیرهای سفارش/صندوق دمو در برابر اجازهٔ رزرو عمومی بر اساس entitlement فروشگاه، و متن/چیدمان جاری نوار اعلان گارسون.
- نام متغیر `module` در تست پرداخت به `pageSource` تغییر کرد تا با متغیر سراسری Node تداخل نداشته باشد.
- رفتار محصول تغییر نکرده است. رزرو برای منوی نمونه همچنان بر اساس تنظیمات و entitlement رستوران قابل دسترسی است؛ ورود آزمایشی، ثبت سفارش عمومی و صندوق نمونه محدود می‌مانند.

## اعتبارسنجی

- تست‌های غیر PostgreSQL: **۲۳۶ موفق، صفر شکست**. تست یکپارچهٔ PostgreSQL اجرا نشد.
- `npm run typecheck -- --incremental false`: موفق.
- `npm run lint`: موفق، **صفر خطا و ۱۵ هشدار از قبل موجود**.
- `next build --webpack`: مرحلهٔ تولید bundle و TypeScript موفق؛ جمع‌آوری دادهٔ صفحات در `/api/affiliate/withdrawals` متوقف شد، چون `DATABASE_URL` در محیط worktree تعریف نشده بود.
- `next build` با Turbopack نیز به محدودیت worktree رسید: `node_modules` یک symlink به بیرون از ریشهٔ worktree است و Turbopack آن را نمی‌پذیرد.

## وضعیت دمو

- سرور توسعه روی پورت ۳۰۰۱ برای بررسی Chrome تلاش شد. کامپایل webpack به dependencyهای Node (`pg` و builtinهایی مانند `fs`) در مسیر instrumentation برخورد کرد و درخواست صفحهٔ اصلی نیز بدون تنظیم `DATABASE_URL` پاسخ ۵۰۰ داد. بنابراین دمو قابل مشاهده و قابل تأیید نشد و لینک آن را به‌عنوان دمو آماده معرفی نمی‌کنیم.
- فایل `.env` خوانده نشد، مقدار محرمانه چاپ/کپی نشد و دیتابیس یا دادهٔ تولید لمس نشد. برای دموی واقعی، محیط محلی باید به یک دیتابیس توسعهٔ جداگانه و migrationهای لازم متصل شود؛ پس از آن می‌توان صفحه را در Chrome بررسی کرد.
- هیچ تغییر موقتی instrumentation برای دور زدن این محدودیت نگه داشته نشده است؛ زمان‌بند موجود و رفتار محصول دست‌نخورده مانده‌اند.
