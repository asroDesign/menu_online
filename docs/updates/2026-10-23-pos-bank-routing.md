# اتصال حساب تسویه و مسیر POS — ۲۰۲۶-۱۰-۲۳

## خواسته و نتیجه

حساب بانکی‌ای که واریزی کارتخوان به آن تعلق دارد اکنون روی تنظیمات همان دستگاه POS تعریف می‌شود. فرم ثبت تسویه سفارش دیگر حساب مقصد POS را نمی‌پرسد. دستگاه نیز در تنظیماتش جداگانه برای «صندوق سفارش» و «کیوسک» مجاز می‌شود؛ کانال روشن بدون انتخاب حساب بانکی همان رستوران ذخیره نمی‌شود.

در تسویهٔ `/dashboard/orders`، هنگام بازکردن فرم یا واردکردن مبلغ POS، اولین دستگاه آنلاین و مجاز صندوق پیش‌فرض است. صندوق‌دار می‌تواند دستگاه دیگری از بین پوزهای مجاز صندوق انتخاب کند؛ حساب مقصد در هر دو حالت از رکورد دستگاه گرفته می‌شود. backend ورودی `posBankAccountId` مرورگر را نادیده می‌گیرد، دستگاه را tenant-scope می‌کند و فعال بودن کانال صندوق و بانک متصل را دوباره اعتبارسنجی می‌کند.

پرداخت کیوسکی هم فقط از POS مجاز برای کانال kiosk استفاده می‌کند. تنظیمات کیوسک اجازه می‌دهد یکی از پوزهای مجاز ترجیح داده شود. هنگام پرداخت، اگر آن دستگاه آفلاین باشد سرور پوز آنلاین مجاز دیگری را انتخاب می‌کند؛ در نبود دستگاه آنلاین سفارش پرداخت کارتخوان نمی‌گیرد. درخواست POS مبلغ سهم پوز، بانک دستگاه، دستگاه و plan حسابداری را snapshot می‌کند.

## پیاده‌سازی

- `src/db/schema.ts` و migration `0047_pos_routing_settings.sql`: افزودن `settlement_bank_account_id`, `cashier_enabled`, `kiosk_enabled` به devices؛ پیش‌فرض کانال‌ها خاموش است تا دستگاه قدیمی تا زمان تنظیم صریح وارد مسیر پرداخت نشود.
- `src/lib/registry-a.ts`: CRUD دستگاه بانک را به همان tenant محدود می‌کند و روشن‌کردن مسیر صندوق/کیوسک بدون بانک را رد می‌کند.
- `src/lib/pos.ts`: جستجوی پوزهای کانال‌دار، ترجیح دستگاه آنلاین، الزام بانک مقصد، تطبیق حساب plan با دستگاه و ساخت plan POS به‌صورت سروری.
- `src/modules/hardware.tsx`: فرم دستگاه POS برای شماره ترمینال، بانک مقصد و دو کانال؛ حساب را از `/dashboard/bank` انتخاب می‌کند.
- `src/modules/orders.tsx` و `src/app/api/orders/[id]/cashier/route.ts`: پیش‌فرض دستگاه صندوق، امکان تغییر دستی، حذف ورودی حساب POS از UI و جایگزینی اجباری حساب ارسالی با حساب ثبت‌شده روی همان POS.
- مسیرهای کیوسک `src/modules/kiosk.tsx`, `src/app/kiosk/[slug]/page.tsx`, `src/app/api/public/[slug]/orders/route.ts`, `src/app/api/public/[slug]/pos/route.ts`, `src/app/api/public/[slug]/pos/[id]/route.ts`: فهرست‌کردن/انتخاب پوزهای مجاز و رسیدگی به offline/retry با همان سیاست.
- `src/lib/registry-c.ts`: درخواست POS صندوق نیز یک دستگاه مجاز صندوق را انتخاب می‌کند و plan دارای بانک مقصد ثبت می‌کند.
- `docs/agents/modules/{devices,orders,accounting}.md` و `docs/agents/module-capabilities.md`: قرارداد داده، نقش‌ها، APIها و مسیر حسابداری به‌روز شد.

## داده، دسترسی و migration

فیلدهای جدید روی جدول `devices` هستند. هیچ اطلاعات بانکی جدیدی از client به عنوان حقیقت مالی پذیرفته نمی‌شود؛ حساب در هر mutation و پیش از settlement از device tenant جاری خوانده می‌شود. API گزینه‌های تسویه هیچ‌وقت `devices.code` را برنمی‌گرداند. `/api/orders/settlement-options` مدیر/صندوق‌دار را می‌پذیرد و حداقل یکی از entitlementهای `cashier_pos` یا `tablet_pos` لازم است تا صفحه تنظیم دستگاه و صندوق هر دو بتوانند از آن استفاده کنند.

پیش از راه‌اندازی، migrationهای `0046` و سپس `0047` را روی دیتابیس هدف اعمال کنید. دستگاه‌های موجود بعد از 0047 `cashier_enabled=false` و `kiosk_enabled=false` خواهند بود؛ مدیر باید حساب و کانال هر دستگاه را در `/dashboard/devices` تنظیم کند. فایل `0047_pos_routing_settings.down.sql` rollback را وقتی حساب یا کانالی متصل باشد متوقف می‌کند؛ برای rollback باید ابتدا تنظیمات POS را پاک/خاموش کنید.

## آزمون و محدودیت

ESLint هدفمند بدون خطا بود و سه هشدار قبلی disable بلااستفاده در فایل‌های registry-c/hardware گزارش شد؛ build دو هشدار CSS قدیمی `@property` دارد. دیتابیس واقعی migration نشده، کارتخوان واقعی در دسترس نبوده و پرداخت/پیام به دستگاه واقعی ارسال نشده است.
