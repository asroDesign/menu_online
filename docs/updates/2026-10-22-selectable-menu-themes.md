# قالب‌های دمو به‌عنوان ظاهر قابل انتخاب منوی دیجیتال

## هدف

چهار طراحی مستقل `/preview/softmenu-test3`, `/preview/softmenu-test`, `/preview/captainm` و `/preview/haftkhan` باید از تنظیمات ظاهر هر رستوران قابل انتخاب باشند. پیش‌نمایش تنظیمات و منوی عمومی پس از ذخیره باید همان ظاهر را روی دادهٔ واقعی رستوران نمایش دهند.

## رفتار پیاده‌سازی‌شده

- چهار گزینه با شناسهٔ پایدار و عنوان فارسی به فهرست مرکزی `src/lib/menu-templates.ts` افزوده شدند. پنج قالب موجود حفظ شده‌اند.
- صفحهٔ `/dashboard/settings#menu-theme` برای هر ۹ قالب کارت تصویری و حالت انتخاب دارد. گزینهٔ انتخابی در `businesses.settings.menuTemplate` ذخیره می‌شود؛ پیوند پیش‌نمایش به `/m/:slug?template=...` می‌رود و کاتالوگ همان کسب‌وکار را نشان می‌دهد.
- شناسه‌ها در مدل `Settings`, پاک‌سازی PATCH کسب‌وکار، خروجی عمومی `buildPublicMenu` و override مجاز query صفحهٔ `/m/[slug]` از یک تابع allowlist اعتبارسنجی می‌شوند. migration دیتابیس نیاز نیست، چون مقدار در JSON تنظیمات موجود ذخیره می‌شود.
- `softmenu-test3` از زمینه و هدر سبز، دسته‌های افقی و کارت‌های عکس افقی استفاده می‌کند؛ `softmenu-test` زمینهٔ بنفش و دسته‌های کاشی‌ای دارد؛ `captainm` تم فضایی با آسمان شب، ستاره‌های CSS و درخشش نئونی بنفش/فیروزه‌ای دارد و دسته‌ها را در راهنمای کناری روی دسکتاپ و نوار قابل پیمایش روی موبایل می‌آورد؛ `haftkhan` دسته‌های آیکنی و شبکهٔ فشردهٔ محصولات دارد. نوار ناوبری پایین نیز برای رنگ هر قالب سازگار است.
- قالب ظاهر را تغییر می‌دهد و داده/منطق منو را جایگزین نمی‌کند: نام و برند، دسته‌ها، محصولات، قیمت و تخفیف، تصویر، موجودی، آلرژن/رژیم، آپشن، سبد، OTP مشتری، پیگیری سفارش، روش‌های پرداخت، رزرو و درخواست گارسون از جریان اصلی tenant باقی می‌مانند.
- routeهای `/preview/:menuId` همچنان دموهای مستقل و غیرعملیاتی با محتوای نمونه هستند؛ انتخاب قالب از تنظیمات، داده‌های این دموها را در منوی واقعی کپی نمی‌کند.

## فایل‌ها و نقش‌ها

- `src/lib/menu-templates.ts`: رجیستری شناسه، نام و توضیح قالب‌ها و اعتبارسنجی allowlist.
- `src/lib/plans.ts`: نوع `Settings.menuTemplate` مشتق‌شده از رجیستری.
- `src/app/api/business/route.ts`: اعتبارسنجی مقدار هنگام ذخیره تنظیمات کسب‌وکار.
- `src/lib/public-menu.ts`: فقط قالب معتبر را به payload عمومی می‌فرستد.
- `src/app/m/[slug]/page.tsx`: override query را برای preview محدود و read-only می‌کند.
- `src/app/dashboard/settings/page.tsx`: کارت‌های انتخاب و previewهای خلاصه؛ preview کاپیتان ام هم ظاهر فضایی را نشان می‌دهد.
- `src/components/menu-client.tsx`: رندر متفاوت دسته/محصول برای قالب‌ها با دادهٔ tenant جاری.
- `src/components/public-menu-navigation.tsx`: ظاهر سازگار نوار منوی مشتری.
- `docs/agents/modules/settings.md`, `docs/agents/core-pages/public-menu.md`, `docs/agents/core-pages/demo-preview.md`, `docs/agents/module-capabilities.md`: راهنمای بازسازی و فهرست قابلیت‌ها.

## سازگاری و محدودیت‌ها

- دادهٔ قدیمی فاقد `menuTemplate` همچنان به `classic` تبدیل می‌شود.
- مقدار نامعتبر در API به `classic` نرمال می‌شود؛ query نامعتبر از قالب ذخیره‌شدهٔ رستوران استفاده می‌کند.
- رنگ‌های زمینهٔ قالب‌ها ثابت و متناسب با نمونه‌ها هستند؛ رنگ انتخابی رستوران برای accent کنترل‌ها، انتخاب دسته و CTAها حفظ می‌شود.
- تصاویر خالی از همان `ProductThumb` و نماد جایگزین موجود استفاده می‌کنند؛ گزینه‌ها و عکس‌های محصول را لازم نیست برای هر قالب دوباره وارد کرد.

## آزمون و پذیرش

`tests/menu-template-options.test.cjs` انسجام allowlist، تنظیمات، API ذخیره، خروجی عمومی، preview و رندر هر چهار قالب را بررسی می‌کند. آزمون‌های موجود `tests/demo-menus.test.cjs` همچنان رفتار و دادهٔ دموهای مستقل را پوشش می‌دهند. `npm run typecheck` و ESLint فایل‌های تغییرکرده باید پیش از انتشار اجرا شوند. بازبینی بصری نهایی باید منوی tenant واقعی را در عرض موبایل و دسکتاپ، با تصویر محصول و بدون تصویر، و با هر ۴ قالب جدید بررسی کند.
