# گزارش بانک و صندوق در اپ Windows آفلاین — ۲۰۲۶-۱۰-۲۷

## رفتار پیاده‌سازی‌شده

یک تب مستقل «بانک و صندوق» در اپ دسکتاپ اضافه شد. این تب آخرین snapshot سرور را از SQLite رمز‌شده می‌خواند و در قطعی اینترنت ماندهٔ صندوق و حساب‌های بانکی، ماندهٔ آغازین حساب، جمع ورودی/خروجی ۳۰ روز اخیر و ۲۵ گردش آخر را نشان می‌دهد. زمان آخرین دریافت و وضعیت نسخهٔ منقضی هم قابل مشاهده است؛ دکمهٔ دریافت تازه همان worker مشترک snapshotها را فعال می‌کند.

## محدوده و حفاظت داده

- API فقط با Bearer terminal مجاز، tenant فعال و entitlementهای `cashier_pos` و `bank_report` پاسخ می‌دهد.
- ماندهٔ جاری برای هر حساب از ماندهٔ آغازین به‌علاوهٔ همهٔ درآمدها و منهای همهٔ هزینه‌ها محاسبه می‌شود؛ جمع بازهٔ ۳۰ روزه جداگانه نمایش داده می‌شود.
- شمارهٔ کامل حساب از API محلی برنمی‌گردد؛ فقط نشانگر ماسک و چهار رقم پایانی به SQLite می‌رود.
- نام حساب/بانک، دسته و شرح گردش برای گزارش ارسال می‌شود و در payload به طول محدود درآمده است.
- سقف ۱۰۰۰ حساب است؛ snapshot عمومی همچنان سقف چهار مگابایت و TTL هفت‌روزه دارد. پاسخ 401/403 نسخهٔ قبلی بانک را از دستگاه پاک می‌کند.
- این نما فقط‌خواندنی است. CRUD حساب بانکی، ثبت گردش/انتقال، صفحه‌بندی تراکنش و انتخاب بازهٔ دلخواه در این مرحله آفلاین نشده‌اند.

## فایل‌های تغییرکرده

- `src/lib/offline-dashboard.ts`: dataset بانک، entitlement، محاسبهٔ tenant-scoped و ماسک شماره حساب.
- `windows-bridge/src-tauri/src/offline.rs`, `windows-bridge/src-tauri/src/main.rs`: تازه‌سازی دوره‌ای snapshot، وضعیت sync و فرمان خواندن از cache.
- `windows-bridge/ui/index.html`, `windows-bridge/ui/pos.js`: تب، وضعیت تازه‌سازی، خلاصه و جداول حساب/گردش.
- `docs/agents/modules/bank.md`, `docs/agents/modules/offline-full-dashboard.md`, `docs/agents/module-capabilities.md`, `docs/agents/core-pages/api-contract-map.md`, `IMPLEMENTATION_STATUS.md`: قرارداد و ماتریس پوشش.

## اعتبارسنجی

`npx tsc --noEmit --incremental false`، ESLint هدفمند، `node --check windows-bridge/ui/pos.js` و `git diff --check` موفق شدند. npm هشدار داد نسخهٔ خودش با Node 18.17.1 سازگاری رسمی ندارد، اما فرمان‌ها موفق بودند. Rust/Tauri در این محیط قابل build نیست چون `cargo` و `rustc` نصب نیستند؛ کد Rust تغییرکرده و بنابراین build ویندوز تأیید نشده است. اتصال دیتابیس، migration و تست یکپارچه اجرا نشد؛ schema تازه‌ای اضافه نشده است. بررسی دسترسی آفلاین تاریخچهٔ سفارش نیز تأیید می‌کند جزئیات سفارش‌های cacheشده بدون اینترنت باز می‌شوند؛ کامل‌بودن همهٔ سوابق قدیمی به اتمام backfill پیش از قطعی وابسته است.
