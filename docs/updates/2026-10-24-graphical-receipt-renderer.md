# اصلاح چاپ گرافیکی فیش — ۲۰۲۶-۱۰-۲۴

## مشکل و علت
قالب قبلی با `|` و `+---+` ساخته می‌شد اما عامل‌های ویندوز هر خط را با فونت نسبی Tahoma چاپ می‌کردند. بنابراین جدول واقعی نبود و ستون‌های فارسی هم‌راستا نمی‌شدند. صفحه HTML به‌تنهایی مسیر چاپ عامل را اصلاح نمی‌کرد.

## پیاده‌سازی
- `src/lib/receipt-layout.ts`: قالب صف اکنون سه ستون شرح کالا، تعداد و مبلغ (تومان) دارد. عرض متنی ۴۸ کاراکتر؛ عرض ستون‌ها ۲۲، ۴ و ۱۲ است. نام/گزینه‌های بلند ادامه پیدا می‌کنند و مبلغ‌های متعارف به خط بعد نمی‌شکنند. `|` موجود در متن ورودی به `¦` تبدیل می‌شود تا ستون جعلی نسازد.
- `windows-bridge/ReceiptRenderer.cs`: موتور مشترک C# برای هر دو عامل. نشانه‌های قاب در صف را به خطوط گرافیکی تبدیل می‌کند؛ خود کاراکترهای جداکننده چاپ نمی‌شوند. متن فارسی با RTL، اندازه‌گیری واقعی فونت، حاشیه داخلی و نسبت ستون‌های ۵۸/۱۴/۲۸ درصد رسم می‌شود. فیش‌های قدیمی دو ستونی و متن ساده تست نیز پشتیبانی می‌شوند.
- چاپ درایور Windows با تصویر ۵۷۶ نقطه‌ای متناسب با عرض قابل چاپ؛ صفحه‌بندی روی مرز سطرهای رندرشده و بدون پنجره پیش‌نمایش. ردیف‌های بسیار بلندتر از یک صفحه ناچار در چند صفحه بریده می‌شوند.
- چاپ مستقیم TCP، USB RAW و serial در عامل دسکتاپ Windows و TCP/RAW در سرویس، تصویر تک‌رنگ ESC/POS در نوارهای ۶۴ خطی می‌فرستد. عرض محافظه‌کارانه ۳۸۴ نقطه برای چاپگرهای رایج ۵۸ و ۸۰ میلی‌متری است؛ روی ۸۰ میلی‌متر تمام عرض کاغذ را پر نمی‌کند. چاپگر باید فرمان raster استاندارد `GS v 0` را پشتیبانی کند؛ برای سایر مدل‌ها از درایور نصب‌شده Windows استفاده شود.
- مسیر ACK، تعداد نسخه، مسیردهی آشپزخانه و منطق مالی تغییر نکرد. شکست رندر خطای چاپ است؛ موفقیت جعلی اعلام نمی‌شود.
- بدون migration و بدون تغییر پروتکل API؛ نسخه‌های قدیمی عامل همچنان متن می‌خوانند و برای اصلاح ظاهر باید به‌روزرسانی شوند. fallback غیر Windows دسکتاپ همچنان متنی است.

## آزمون و انتشار
۱۸ تست مرتبط Node موفق شد. تست واقعی Windows در `windows-bridge/test-receipt-renderer.ps1` به هر دو workflow اضافه شد: رندر فارسی در عرض ۳۸۴ و ۵۷۶، بررسی پیکسل خط قاب، مرزهای صفحه‌بندی و ساختار تمام بلوک‌های ESC/POS. دو تصویر نمونه به‌صورت artifact ساخته می‌شود؛ هیچ دستگاه یا سفارش واقعی را چاپ نمی‌کند.
کل مجموعه Node: ۱۸۲ تست، ۱۷۵ موفق، ۷ تست دیتابیس ردشده از اجرا (skipped)، بدون شکست. `npm run typecheck -- --incremental false`، lint فایل تغییرکرده و `git diff --check` موفق شدند. محیط محلی macOS است؛ اجرای System.Drawing Windows و چاپ فیزیکی محلی قابل انجام نیست. موفقیت تست متن معادل تأیید چاپ روی سخت‌افزار نیست.

## راهنمای استقرار
پس از موفقیت workflow، نصب‌گر جدید عامل مورد استفاده را نصب کنید. نصب‌گر سرویس سرویس قبلی را جایگزین می‌کند؛ برنامه دسکتاپ نیز باید بسته و نسخه جدید اجرا شود. فقط یک عامل برای هر کد دستگاه فعال باشد. سپس یک فیش واقعی با نام بلند، گزینه اضافه و مبلغ چندرقمی روی چاپگر هدف بررسی شود. چاپ RAW وابسته به مدل دستگاه است.
