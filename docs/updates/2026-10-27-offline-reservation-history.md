# آرشیو آفلاین تاریخچهٔ رزروها

## هدف

هنگام قطعی اینترنت، کارکنان بتوانند رزروهای قبلی و جزئیات آن‌ها را از داده‌های دریافت‌شدهٔ دستگاه مشاهده کنند. تاریخچهٔ سفارش‌ها و جزئیات سفارش نیز طبق ماژول صندوق آفلاین در SQLite رمز‌شده نگه‌داری و بدون اتصال قابل مشاهده است.

## پیاده‌سازی

- مسیر `GET /api/offline-dashboard/reservation-history` تاریخچه را با cursor ترکیبی زمان ایجاد و شناسه، ۵۰ ردیف در هر صفحه، فقط برای کسب‌وکار متصل و با entitlementهای صندوق و رزرو برمی‌گرداند.
- عامل Windows صفحه‌های رزرو را حداکثر در batchهای ۲۰تایی دریافت می‌کند. تا تکمیل آرشیو هر ۳۰ ثانیه ادامه می‌دهد؛ بعد از آن snapshot جاری رزرو هر ۶۰ ثانیه تازه می‌شود.
- payload رزرو در جدول `offline_reservation_history` با همان محافظ رمزگذاری محلی DPAPI ذخیره می‌شود. SQLite `user_version` از ۴ به ۵ ارتقا یافت و migration قبلی دست‌نخورده می‌ماند.
- رابط رزرو فهرست صفحه‌ای و مودال جزئیات را از SQLite می‌خواند. ردیف‌هایی که فقط در آرشیو قدیمی هستند، فقط‌خواندنی‌اند؛ تغییر وضعیت فقط برای رزروهای موجود در snapshot تازه و با PIN مدیر فعال می‌ماند.
- پاسخ 401/403 پس از اتصال، snapshot و آرشیو رزرو این tenant را پاک می‌کند. تاریخچهٔ دریافت‌نشده هنگام قطعی قابل نمایش نیست؛ برای در دسترس بودن کامل باید دریافت اولیه پیش از قطعی تمام شود.
- جزئیات رزروهای قدیمی‌تر همان وضعیت ثبت‌شده هنگام دریافت صفحه را نشان می‌دهند؛ snapshot آخرین ۱۰۰ رزرو برای داده‌های جاری تازه‌سازی می‌شود.

## فایل‌ها

- `src/lib/offline-dashboard.ts`: API صفحه‌بندی‌شده و tenant-scoped تاریخچهٔ رزرو.
- `src/app/api/offline-dashboard/reservation-history/route.ts`: route با پاسخ no-store.
- `windows-bridge/offline-core/src/lib.rs`: جدول، migration نسخهٔ ۵، ذخیره/صفحه‌بندی/پاک‌سازی آرشیو رمز‌شده.
- `windows-bridge/src-tauri/src/offline.rs`: دریافت دوره‌ای آرشیو و اتصال فرمان UI به صفحهٔ محلی.
- `windows-bridge/ui/pos.js` و `windows-bridge/ui/index.html`: نمایش تاریخچه، جزئیات و پیمایش صفحات قدیمی.
- `docs/agents/modules/offline-full-dashboard.md`: مرجع جاری ماژول و محدودیت‌های آفلاین.
