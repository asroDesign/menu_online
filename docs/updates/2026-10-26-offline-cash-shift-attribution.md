# انتساب فروش آفلاین به شیفت صندوق — ۲۰۲۶-۱۰-۲۶

## رفتار

- هنگام تسویه سفارش صندوق، `settleOrder` برای سفارش‌های cashier/waiter بازهٔ شیفت‌های همان کسب‌وکار را با زمان ثبت سفارش تطبیق می‌دهد.
- برای فروش آفلاین، هم شیفت باز و هم شیفتی که پس از فروش بسته شده می‌تواند منطبق باشد؛ بازهٔ `openedAt <= occurredAt <= closedAt` ملاک است. انتخاب و اتصال شیفت در همان transaction با قفل سطر انجام می‌شود.
- اگر فروش زماناً داخل هیچ شیفتی نباشد، ثبت سفارش/تسویه به خاطر نبود شیفت متوقف نمی‌شود و تراکنش با `shiftId = null` ذخیره خواهد شد. این از انتساب به شیفتی نامرتبط جلوگیری می‌کند.
- snapshot شیفت تا sync فروش را در جمع رسمی نشان نمی‌دهد. پس از همگام‌سازی و refresh snapshot، تراکنش در جمع شیفت منطبق دیده می‌شود. تب شیفت صندوق همچنان فقط‌خواندنی است و باز/بستن شیفت آفلاین اضافه نشده است.
- تاریخچهٔ سفارش‌های server و جزئیات snapshotشده در SQLite رمز‌شدهٔ Windows باقی می‌ماند. فهرست/مودال جزئیات بدون تماس شبکه کار می‌کنند؛ آرشیو کامل باید پیش از قطعی با تکمیل backfill دریافت شده باشد.

## فایل‌ها

- `src/lib/orders.ts`: انتخاب tenant-scoped شیفت متناظر زمان ثبت در transaction تسویه.
- `docs/agents/modules/offline-pos.md`: قرارداد تسویه و شیفت صندوق آفلاین.
- `docs/agents/modules/offline-full-dashboard.md`: وضعیت شیفت و مرزهای آفلاین.
- `docs/agents/core-pages/api-contract-map.md`: قرارداد sync آفلاین.
- `IMPLEMENTATION_STATUS.md`: وضعیت، اعتبارسنجی و محدودیت‌های باقی‌مانده.

## اعتبارسنجی و محدودیت

- اجرای typecheck و ESLint هدفمند مجاز است؛ دیتابیس، migration و تست integration اجرا نمی‌شوند.
- build Rust/Tauri نیازمند `cargo` است؛ این ابزار در محیط موجود نیست.
- زمان مورد اعتماد این طراحی همان `occurredAt` فعلی سفارش آفلاین است که API آن را در lease هفت‌روزهٔ catalog محدود می‌کند؛ ساعت سخت‌افزاری معتبر یا امضای زمان دستگاه افزوده نشده است.
