# هماهنگ‌سازی رنگ صفحه‌های خطا با رنگ سازمانی — ۲۰۲۶-۱۰-۳۰

## مسئله و تغییر

- صفحهٔ مستقل `/502` از پالت سبز ثابت استفاده می‌کرد. اکنون رنگ سامانه را با `getPlatformBranding()` می‌خواند و متغیرهای CSS را از `brandThemeStyle()` می‌سازد؛ پس زمینه، شبکه، پنل وضعیت، کارت‌ها، برچسب‌ها و دکمه‌ها با رنگ انتخاب‌شده در پنل مدیریت هماهنگ‌اند.
- اگر دسترسی پایگاه‌داده هنگام پاسخ ۵۰۲ ممکن نباشد، route با رنگ پیش‌فرض باز هم HTML خطای ۵۰۲ را برمی‌گرداند.
- صفحهٔ ۴۰۴ تنظیمات برند را در server render می‌گیرد تا پیش از hydration نیز رنگ، نام سامانه و لوگوی جاری درست باشد. در صورت خطای خواندن تنظیم، fallback استاندارد استفاده می‌شود.
- صفحهٔ global error همچنان مستقل از CSS layout است؛ سطح و آیکن‌ها اکنون از توکن‌های اولیه/اصلی برند استفاده می‌کنند و متغیر محتوای پایه نیز در تم خطا تعریف شده است. خطای هشدار ظاهری، که در این صفحه معنای نوع خطا ندارد، از پالت ثابت زرد به رنگ برند منتقل شد.

## بررسی

- مسیر ناموجود در Chrome دسکتاپ بررسی شد؛ route ۵۰۲ نیز در Chrome رندر شد. رنگ آبی پیش‌فرض و نام سامانه از تنظیم محلی دریافت شدند.
- `curl` برای مسیر ناموجود status برابر 404 و برای `/502` status برابر 502 را تأیید کرد.
- `npm run typecheck -- --incremental false`، ESLint هدفمند پنج فایل و `git diff --check` موفق شدند. تست جداگانه‌ای برای رنگ در پایگاه‌دادهٔ دیگری اجرا نشد؛ پالت‌های رنگ از ورودی معتبر `brandThemeStyle` ساخته می‌شوند.

## محدوده و محدودیت

تغییر روی صفحه‌های خطای Next و route محلی `/502` اثر دارد. خطای 502 صادرشده از CDN، reverse proxy یا میزبان پیش از رسیدن درخواست به Next همچنان باید در تنظیمات همان سرویس به `/502` هدایت شود. رنگ‌های مستقل قالب‌های منوی کسب‌وکارها، هشدارهای معنایی محصول و رنگ‌های تصویر/نمودار جزو این تغییر نیستند.
