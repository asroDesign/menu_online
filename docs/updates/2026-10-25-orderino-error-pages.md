# بازطراحی صفحه‌های خطا با مرجع ورود Orderino

تاریخ: ۲۰۲۶-۱۰-۲۵

## هدف

صفحه‌های خطای MenuPeak با نگاه به [صفحهٔ ورود Orderino](https://orderino.app/login) و سپس تصویر اسکرین‌شات خطای فرستاده‌شده توسط کاربر، بدون باز کردن سایت در Chrome بازطراحی شوند.

## بررسی مرجع

ورود Orderino با درخواست HTTP عمومی و خواندن CSS/assetهای منتشرشده بررسی شد؛ Chrome باز نشد. HTML صفحهٔ ورود فقط skeleton داشت. بعد کاربر اسکرین‌شات صفحهٔ خطای Orderino را ضمیمه کرد. تصویر هدف قاب سفید بزرگ روی زمینهٔ شبکه‌ای روشن، preview خطا در پنل سبز سمت چپ، عنوان/توضیح و دو دکمه در سمت راست و چهار کارت دسترسی سریع را نشان می‌دهد. پیاده‌سازی نهایی همین ساختار و پالت را دنبال می‌کند؛ آزمون بصری Chrome انجام نشده است.

## رفتار پیاده‌سازی‌شده

- `src/components/system-error-screen.tsx` پوستهٔ مشترک RTL و واکنش‌گرا برای ۴۰۴ و خطای معمول صفحه می‌سازد. در نمایشگر بزرگ، preview وضعیت سبز در سمت چپ و عنوان/دکمه‌ها/دسترسی سریع در سمت راست‌اند؛ در موبایل دو ستون به یک ستون تبدیل می‌شوند.
- `src/app/not-found.tsx` همین پوسته را برای ۴۰۴ استفاده می‌کند و مسیرهای بازگشت به خانه و ورود را نشان می‌دهد.
- `src/app/error.tsx` ظاهر مشترک را به کار می‌گیرد، `reset()` را نگه می‌دارد، رویداد قبلی را ثبت می‌کند و در صورت وجود digest آن را برای پشتیبانی نمایش می‌دهد.
- `src/app/global-error.tsx` برای وقتی که shell اصلی در دسترس نیست، HTML/CSS مستقل و واکنش‌گرا دارد؛ `reset()` و digest حفظ شده‌اند.
- `src/app/502/route.ts` مسیر `/502` را به پاسخ مستقل HTTP 502 با HTML/CSS درون‌خطی تبدیل می‌کند. «صفحهٔ ۵۰۲» در Next قابل سرویس‌دهی است؛ اما خطای reverse proxy که قبل از رسیدن درخواست به Next رخ می‌دهد با این route قابل کنترل نیست و باید در سرویس میزبان به `/502` نگاشت شود.

## مرزهای رفتار

کد خطای UI صفحه‌های runtime را عمداً ۵۰۰ نگه می‌دارد؛ نمایش ۵۰۲ برای خطای عادی برنامه نادرست خواهد بود. مسیر `/502` پاسخ واقعی 502 می‌دهد، ولی کد reverse proxy یا بارگذار ابری در این تغییر دست‌کاری نشده است. برند قابل تغییر از API برند عمومی در پوستهٔ client خوانده می‌شود و در خطا به نام MenuPeak fallback می‌کند؛ route مستقل 502 برای تضمین دسترس‌پذیری مستقل از سرویس برند است.

## اعتبارسنجی

- ESLint هدفمند فایل‌های تغییرکرده موفق شد.
- `npm run typecheck` و `npm run build` موفق شدند. Build دو هشدار قبلی DaisyUI دربارهٔ `@property --radialprogress` و `@property --aura-angle` را چاپ کرد.
- با سرور production محلی و بدون Chrome، `GET /502` با status `502` و محتوای مسیرهای سریع تأیید شد؛ یک مسیر تصادفی ناموجود نیز `404` برگرداند و همان دسترسی‌های سریع را داشت.
- `git diff --check` موفق شد. پیکربندی reverse proxy و آزمون تصویری Chrome انجام نشدند.
