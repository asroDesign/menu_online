# تاریخچه و جزئیات سفارش در حالت آفلاین — ۲۰۲۶-۱۰-۲۶

## نیاز

کاربر صندوق ویندوز باید هنگام قطع اینترنت بتواند به سفارش‌های ثبت‌شده در همان دستگاه و جزئیات فاکتور دسترسی داشته باشد. نمایش صرف مبلغ و شناسه کافی نبود و اتکا به منوی فعلی برای نام کالا یا قیمت تاریخی می‌توانست بعد از تغییر کاتالوگ اطلاعات اشتباه نشان دهد.

## تغییر اجرایی

- SQLite محلی به نسخهٔ ۳ ارتقا یافت. migration در `windows-bridge/offline-core/src/lib.rs` فقط ستون nullable `sales.display_payload` را اضافه می‌کند.
- لحظهٔ ثبت سفارش، هسته از catalog معتبر همان فروش snapshot نمایشی شامل نام کالا/افزودنی‌ها، قیمت‌های زمان ثبت، تعداد/وزن، مبالغ اقلام، مالیات/خدمات، میز، اطلاعات مشتری، یادداشت و مشخصات تسویه‌پذیر را می‌سازد. snapshot جدا از payload ارسال به سرور نگه داشته می‌شود و همراه سفارش در transaction محلی ذخیره می‌شود.
- `offline_status` سوابق صد سفارش اخیر و جزئیاتشان را از پایگاه محلی برمی‌گرداند. فرمان `offline_history` صفحه‌های قدیمی‌تر ۱۰۰تایی را بدون شبکه می‌خواند.
- در صندوق دکمهٔ «جزئیات» برای هر ردیف، مودال جزئیات کامل فاکتور را باز می‌کند. اطلاعات مالیاتی و اقلام تاریخی از snapshot همان فروش خوانده می‌شوند؛ وضعیت و نوع پرداخت از payload جاری خوانده می‌شود تا پرداخت بعدی هم درست باشد.
- برای فروش‌های پیش از schema v3، payload قبلی دست‌نخورده می‌ماند. رابط اطلاعات پایه و شناسهٔ اقلام را نمایش می‌دهد و آشکارا می‌گوید که نام/قیمت تاریخی ذخیره نشده بود.

## حدود قابلیت

آرشیو شامل فروش‌های محلی همان دستگاه است. این تغییر سفارش‌های سایت یا صندوق‌های دیگر را خودکار به دستگاه نمی‌آورد. مرور تاریخچه برای هر ۱۰۰ سفارش یک صفحه می‌خواند. فاکتورهای قدیمی‌تر از این نسخه ممکن است جزئیات نام‌دار اقلام را نداشته باشند، زیرا پیش‌تر snapshot آن داده ذخیره نشده بود.

## اعتبارسنجی

طبق محدودیت اعلام‌شدهٔ کاربر، تست خودکار و دیتابیس اجرا نشدند. `npm run typecheck`، `node --check windows-bridge/ui/pos.js` و `git diff --check` موفق شدند. ابزارهای `cargo` و `rustc` در محیط حاضر نیستند؛ بنابراین کامپایل Rust/Tauri تأیید نشده است. npm هشدار داد که نسخهٔ نصب‌شدهٔ npm 11.3.0 با Node 18.17.1 پشتیبانی رسمی ندارد، هرچند typecheck موفق شد.
