# نمودار بازدید منو در داشبورد رستوران

## هدف

نمایش روند بازدید منوی دیجیتال در صفحهٔ اصلی داشبورد رستوران، برای اینکه مدیر بتواند تغییر توجه مشتریان به منو را کنار شاخص‌های فروش ببیند.

## تغییرات انجام‌شده

- `GET /api/stats` شمار رویدادهای `menu_view` را از جدول موجود `menu_events` بر اساس روز محلی تهران گروه‌بندی می‌کند و ۱۴ روز روزانه را برمی‌گرداند.
- فیلتر سرور با `business.id` حاصل از نشست احرازشده انجام می‌شود. دادهٔ یک کسب‌وکار دیگر از ورودی کاربر پذیرفته نمی‌شود.
- سری روزانه برای روزهای بدون رویداد مقدار صفر می‌سازد؛ مجموع دوره و میله‌های روزانه در `/dashboard` نمایش داده می‌شوند.
- تاریخ‌ها با formatter شمسی مشترک‌اند و نمودار در اندازه‌های موبایل و دسکتاپ بدون وابستگی chart package اضافی رسم می‌شود.
- متن رابط روشن می‌کند که شمارش بر اساس رویداد است و بازدیدهای تکراری یکتا‌سازی نمی‌شوند. رویدادهای منوی preview فقط وقتی منوی واقعی در حال استفاده است ثبت می‌شوند.
- مستند بازسازی داشبورد و کاتالوگ قابلیت‌ها به‌روز شد.

## فایل‌ها و نقش آن‌ها

- `src/app/api/stats/route.ts`: query tenant-scoped برای رویدادها، گروه‌بندی `Asia/Tehran` و افزودن سری به پاسخ آمار.
- `src/lib/menu-views-core.ts`: ساخت سری روزانهٔ ثابت و پرکردن روزهای بدون رویداد با صفر.
- `src/modules/overview.tsx`: نمودار واکنش‌گرا، مجموع دوره، تاریخ‌های شمسی، عنوان‌های راهنما و متن دسترس‌پذیری.
- `tests/menu-views-dashboard.test.cjs`: آزمون تکمیل سری و قرارداد tenant/timezone/UI.
- `docs/agents/modules/dashboard-overview.md`, `docs/agents/module-capabilities.md`, `docs/agents/README.md`: مشخصات جاری ماژول و نقشهٔ عامل.

## داده، دسترسی و سازگاری

- جدول `menu_events` و ثبت عمومی `menu_view` پیش از این قابلیت وجود داشتند؛ migration یا تغییر schema لازم نیست.
- API داشبورد با `withAuth` محافظت می‌شود و همان guard مدیر/حسابدار فعلی را حفظ می‌کند. خود query به `business.id` نشست محدود است.
- بازدیدها تعداد eventهای پذیرفته‌شده‌اند، نه کاربران یکتا یا نشست‌های یکتا. ارقام ساختگی از سفارش‌ها یا بازدیدهای محصول محاسبه نمی‌شوند.
- polling قبلی داشبورد هر ۱۵ ثانیه پاسخ را تازه می‌کند؛ نمودار از همان پاسخ استفاده می‌کند.
