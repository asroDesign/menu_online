# مدیریت تأمین‌کنندگان انبار در Windows آفلاین — ۲۰۲۶-۱۰-۲۷

## هدف و دامنه

تب انبار برنامهٔ Windows اکنون اجازه می‌دهد مدیرِ دارای PIN محلی، تأمین‌کننده را هنگام قطعی اینترنت بسازد، اطلاعاتش را ویرایش کند یا برای خریدهای جدید غیرفعال کند. داده‌ها در outbox رمز‌شدهٔ دستگاه صف می‌شوند و پس از اتصال به سرور ارسال می‌شوند. تأمین‌کنندهٔ تازه تا دریافت snapshot جدید و تأیید سرور در فاکتور خرید قابل انتخاب نیست. حذف فیزیکی عمداً پشتیبانی نمی‌شود تا سوابق خرید و حسابداری حفظ شوند.

## رفتار و قرارداد

- snapshot انبار حداکثر ۱۰۰۰ تأمین‌کننده به همراه نام، مسئول تماس، تلفن، نشانی، شناسهٔ مالیاتی، اطلاعات بانکی، یادداشت، وضعیت فعال و وجود حساب پرداختنی را برمی‌گرداند.
- ساخت با `supplier_create` و تغییر با `supplier_update` انجام می‌شود. فرمان شامل شناسهٔ UUID، کسب‌وکار، snapshot و revision مبناست؛ طول داده‌ها و فیلدهای مجاز هم در Rust و هم در API بررسی می‌شود. تغییر نیازمند baseline کامل تأمین‌کننده است تا سرور ویرایش هم‌زمان را به‌جای بازنویسی خاموش، با 409 رد کند.
- UI سطرهای cacheشده و ساخت‌های منتظر sync را جدا نشان می‌دهد. خطاهای conflict/rejected از فهرست ناپدید نمی‌شوند؛ وضعیت فرمان و علت قابل مشاهده است. PIN مدیر محلی و snapshot تازه برای ثبت لازم است.
- سرور terminal فعال، tenant، اشتراک‌های صندوق/انبار/حسابداری، snapshot معتبر و idempotency فرمان را بررسی می‌کند. قفل advisory کسب‌وکار پیش از خواندن ردیف‌ها گرفته می‌شود و تراکنش `read committed` اجازه می‌دهد کنترل نام تکراری پس از تکمیل فرمان رقیب تازه بماند.
- ایجاد سرفصل تفصیلی پرداختنی، سطر تأمین‌کننده و command ledger در یک تراکنش اتمی انجام می‌شود. تغییر نام تأمین‌کننده و حساب تفصیلی مرتبط نیز در همان تراکنش است. تخصیص کد تفصیلی با قفل مستقل حسابداری میان مسیر آنلاین/آفلاین سریال می‌شود.
- migration `0080_offline_inventory_suppliers.sql` allowlist جدول فرمان را گسترش می‌دهد. down migration در صورت وجود سابقهٔ این فرمان‌ها rollback را متوقف می‌کند؛ حذف تاریخچهٔ audit مجاز نیست.

## فایل‌های اصلی

- `windows-bridge/ui/index.html`, `windows-bridge/ui/pos.js`: جدول، فرم ساخت/ویرایش، صف محلی و وضعیت همگام‌سازی.
- `windows-bridge/offline-core/src/lib.rs`, `windows-bridge/src-tauri/src/offline.rs`, `windows-bridge/src-tauri/src/main.rs`: صف SQLite رمز‌شده، فرمان‌های Tauri و وضعیت outbox.
- `src/lib/offline-dashboard.ts`, `src/lib/offline-inventory.ts`, `src/app/api/offline-dashboard/inventory/route.ts`: snapshot و اعتبارسنجی/اعمال سمت سرور.
- `src/lib/accounting.ts`: ساخت اتمی سرفصل تفصیلی پرداختنی و تخصیص امن کد.
- `src/db/migrations/0080_offline_inventory_suppliers.sql` و فایل down: allowlist و محافظت rollback.
- قرارداد ماژول در `docs/agents/modules/inventory.md`، ماتریس قابلیت‌ها در `docs/agents/modules/offline-full-dashboard.md` و قرارداد endpoint در `docs/agents/core-pages/api-contract-map.md` به‌روز شده‌اند.

## بررسی و محدودیت‌ها

- تست‌های قراردادی ایجادشده مسیر API، Tauri/Rust، allowlist و اتمی‌بودن ثبت سرفصل/تأمین‌کننده/ledger را بررسی می‌کنند؛ آن‌ها جایگزین آزمون PostgreSQL هم‌زمان نیستند.
- migration روی دیتابیس اجرا نشده و داده‌ای از محیط اصلی تغییر نکرده است.
- ابزار `cargo`/`rustc` در محیط موجود نیست؛ کامپایل Rust/Tauri و اجرای واقعی Windows انجام نشده است.
- حذف فیزیکی تأمین‌کننده و استفاده از تأمین‌کنندهٔ صف‌شده در فاکتور پیش از sync در این برش وجود ندارد.
