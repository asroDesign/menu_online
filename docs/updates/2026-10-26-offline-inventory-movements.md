# خروج و شمارش موجودی در حالت آفلاین

در تب انبار اپ Windows برای هر قلم فعال و دارای ردیابی موجودی دو عملیات به منوی گردش اضافه شد: «خروج» برای کم‌کردن مقدار مصرف‌شده و «شمارش» برای ثبت موجودی نهایی که واقعاً در محل شمرده شده است. هر دو در کنار فاکتور ورود و ضایعات قرار دارند و تا رسید سرور به‌عنوان درخواست محلی/غیرقطعی نمایش داده می‌شوند.

## رفتار رابط و ذخیره‌سازی محلی

- خروج مقدار مثبت، توضیح اختیاری و PIN مدیر محلی می‌گیرد؛ موجودی پیش‌بینی‌شدهٔ محلی از snapshot و فرمان‌های pending/synced همان نسخه محاسبه می‌شود و خروج بیش از آن رد می‌شود.
- شمارش مقدار نهایی موجودی را می‌گیرد؛ مقدار صفر مجاز است و مقدار برابر موجودی پیش‌بینی‌شده درخواست بی‌اثر محسوب می‌شود.
- هر درخواست با نوع عملیات، شناسهٔ قلم، مقدار، موجودی/بهای مبنا، زمان و توضیح در outbox رمز‌شدهٔ SQLite قرار می‌گیرد. دکمه‌های ورود، خروج، شمارش و ضایعات برای کالای متعارض تا snapshot تازه غیرفعال‌اند.
- وضعیت فرمان، توضیح و خطای احتمالی در فهرست گردش‌های ثبت‌شده روی دستگاه دیده می‌شود. مقدار snapshot رسمی از projection محلی جدا نمایش داده می‌شود.

## بازبینی و ثبت روی سرور

`POST /api/offline-dashboard/inventory` اکنون `inventory/movement` را می‌پذیرد. سرور terminal، کسب‌وکار، entitlementهای صندوق/انبار/گردش، شناسهٔ idempotency، snapshot معتبر همان دستگاه و فعال/قابل‌ردیابی بودن کالا را دوباره بررسی می‌کند. پیش از اعمال، قفل کسب‌وکار و قلم گرفته می‌شود و stock و cost جاری با مبنای فرمان تطبیق می‌یابند؛ کمبود موجودی یا تغییر هم‌زمان خروج را conflict می‌کند.

برای `out` و `adjust` سرور از `applyStockReceipt` استفاده می‌کند. رسید، گردش، ماندهٔ جدید، اثر حسابداری متناسب با بهای قلم و command ledger در همان PostgreSQL transaction نوشته می‌شوند. شناسهٔ فرمان به‌عنوان request key از اعمال دوباره جلوگیری می‌کند. فرمان خطادار با دادهٔ جدید rewrite نمی‌شود؛ کاربر باید snapshot تازه بگیرد و تصمیم خود را دوباره ثبت کند.

Migration `0067_offline_inventory_movements.sql` action `movement` را مجاز می‌کند و actionهای رزرو و مطالبات قبلی را نیز حفظ می‌کند. rollback فقط وقتی ممکن است که هیچ فرمان `inventory/movement` ثبت نشده باشد؛ rollback سایر actionهای پیشین را نیز مجاز نگه می‌دارد. Migration اجرا نشده است.

## محدوده و بررسی

انتقال بین انبارها، ساخت کالای تازه، CRUD فروشنده، lot/expiry و recipe همچنان آفلاین نیستند. دسترسی آفلاین به تاریخچه و جزئیات سفارش همچنان الزام این اپ است: سفارش‌های محلی و سروری cacheشده در SQLite رمز‌شده می‌مانند؛ آرشیو سفارش‌های سرور با صفحه‌بندی cursorدار تا تکمیل backfill پر می‌شود و جزئیات cacheشده بدون شبکه باز می‌شوند. برای مشاهدهٔ سابقهٔ کامل کسب‌وکار، دستگاه باید پیش از قطعی اینترنت آنلاین بماند تا backfill کامل شود.

اعتبارسنجی انجام‌شده: `npm run typecheck`، ESLint هدفمند برای route/helper، `node --check windows-bridge/ui/pos.js` و `git diff --check` موفق شدند. بنا بر محدودیت کاربر تست پایگاه داده، migration و integration اجرا نشدند. `cargo` و `rustc` در محیط حاضر نیستند، بنابراین کامپایل Rust/Tauri تأیید نشده است.
